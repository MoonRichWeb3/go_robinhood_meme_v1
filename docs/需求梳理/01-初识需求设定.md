## 结论先行

v0 做三件事：听新盘、盯聪明钱、从流水里筛优质项目。先发现、先记账，不下单。

1. **新盘入库（四类独立模型）**  
   覆盖：Pons V2、o1 股票配对、o1 加密货币配对、**Long**。每类一张表、一套 Go 结构体。公共信息可以有一张很瘦的目录表，**禁止**把曲线地址、股票 quote、Doppler hook、毕业阈值塞进同一个「万能 Launch」对象。

2. **聪明钱包主数据**  
   一张 `smart_wallets`。**以 SQLite 里的行准**（导入方式不在本需求）。进程 **不能只在启动时读一次名单**：增删改、暂停、拉黑要在运行中被扫块感知（见 4.2）。评分必须折 USD。级别由分数切档。名单地址可以是 EOA，也可以是 Deployer 合约。

3. **盯盘流水**  
   **当前** `status=active` 的地址一旦发盘或买入/卖出四类盘口（名单按 4.2 热更新）：**中文**结构化日志打到 stdout，同时写入 `wallet_events`（幂等）。买卖 **只入库聪明钱**，含 GMGN 等多跳。用户地址取实际拿到/交出代币的钱包，不要用 v4 `Swap.sender`。

4. **价格分两路**  
   交易表记下聪明钱每笔 **实际成交单价（U）和数量**，用来算真实盈亏（FIFO，见 5.3）。币对表（`launch_index`）只给人看 **单价 U**：**仅已入库且本窗口内有成交** 的资产才写库，默认 **每 3 秒刷一次**，不要每笔成交 UPDATE。明细表 `launch_*` **不存价格**。算法见调研 `06` / `07` / `09`。折 USD 规则见 4.4。

运行形态：Go 常驻扫块 + **go-zero** 最小只读 HTTP + 本地 SQLite + Docker 挂卷。时间戳一律 UTC。reorg **不回滚**已写入事件。

## 1. 产品目标与非目标

### 1.1 要达成

| 目标 | v0 验收 |
| --- | --- |
| 新盘不漏（四类之内） | 工厂事件出现后，对应类型表有一行，且能回答：分类、配对名称、创建人、创建时间 |
| 聪明钱可运营 | 运行中改 SQLite 就能增删改；**不必重启**。新增 `active` 的下一轮刷新后开始命中；删除/暂停/拉黑后不再打聪明钱日志、不再写新流水。评分可解释 |
| 行为可追溯 | 发盘/买/卖都能在**中文日志**和表里对上交易、合约、方向、金额、折 USD 快照 |
| 成交与盈亏 | 聪明钱买卖能在交易表对上数量、成交单价 U；按 FIFO 能算出已实现盈亏（例：买 100×1U、卖 50×2U → 盈亏 50U） |
| 币对单价 U | 已监控且有过成交的项目，列表能读到单价 U；表更新不超过约 3 秒一次，无成交的行不刷 |
| 帮你找优质项目 | 能列出：聪明钱发的盘、多聪明钱同买、某钱包胜率高的盘（v0 用 SQL / 只读 API，信号表可后做） |

### 1.2 明确不做（v0）

- 自动买入/卖出、跟单下单、私钥热钱包
- Bags、hood.fun、pools.trade、Bankr 等（Long 已纳入；其它仍范围外）
- Debot/GMGN 实时爬虫当主数据源（可作名单出处标签；链上事件才是事实）
- 钱包 CSV/API 导入方案（不限定、本文件不设计）
- 多链、回测 UI、对外公网鉴权产品
- reorg 回滚 SQLite

## 2. 监控范围（四类盘口）

分类 **只由创建交易打到的工厂/入口决定**，不用 Debot 猫标、不用代币名字猜测。

| 分类代码 | 含义 | 链上入口（调研已核） | 配对长什么样 |
| --- | --- | --- | --- |
| `pons` | Pons V2 内盘曲线，可毕业进 v4 | Factory `0x7eD598Bc…EC7e` 的 `TokenLaunched`；前端常打 LaunchAndBuy `0xe33E9E47…2948` | quote = **ETH `0x0` 或 USDG**，以后还可能是股票 token |
| `o1_stock` | o1 股票配对，创建即 v4 + LaunchHook | Factory `0xe64AC411…F297` 的 `Launched` | quote = **已注册股票代币**（如 WYFI）；代币地址以 `01` 结尾 |
| `o1_crypto` | o1 加密货币配对 | Factory `0x411F2128…0Ba5` 的 `Launched` | quote = **ETH 或 USDG**；Hook 与股票盘 **不是同一个** |
| `long` | LongLauncher → Doppler Airlock，创建即 v4 | LongLauncher `0x22e99278…eeED` 的 `LaunchCreated` | quote = `numeraire`（已核样本为股票代币 AMZN/MRNA）；**不要**把全部 Airlock `Create` 算 Long |

监听骨架（实现时按调研拆 adapter，不要一个 parser 写四类 ABI）：

```text
eth_getBlockReceipts / 日志订阅
        ├── Pons TokenLaunched / CurveBuy / CurveSell / PoolGraduated
        ├── Long LaunchCreated + PoolManager.Swap（poolId ∈ launch_long）
        ├── o1_stock Launched + PoolManager.Swap（hooks=股票 LaunchHook）
        └── o1_crypto Launched + PoolManager.Swap（hooks=加密 LaunchHook）
```

新盘四类全听。Pons 毕业事件要听（更新 `phase`）。**币对表价格**：只对 **已入库** 盘口，且 **确实出现过成交** 才进入刷新队列（Pons 全链 `CurveBuy`/`CurveSell`、已知 `poolId` 的 `Swap`，不限聪明钱）。毕业后全市场 Swap **仍不写交易表**，但该 `poolId` 属于已入库盘则可把最新成交单价 U 记入内存，等 3 秒刷 `launch_index`。买卖流水只入库聪明钱相关。无成交的新盘：币对表单价 U 留空，不要用创建时的中间价冒充成交价。

## 3. 需求一：新盘基本信息入库（独立类型）

### 3.1 为什么不能一张「Launch」宽表

| | Pons | o1 股票 | o1 加密 | Long |
| --- | --- | --- | --- | --- |
| 内盘曲线 | 每币一个 `curve` | 无 | 无 | 无 |
| 报价资产 | ETH / USDG /（可能）股票 | 股票代币 | ETH / USDG | `numeraire`（已核为股票） |
| 池身份 | 毕业后才有 v4 pool | 创建即有 `pool_id` | 创建即有 `pool_id` | 创建即有 `pool_id` |
| Hook | 毕业后才是 Pons meme hook | 股票 LaunchHook | 另一套 LaunchHook | DopplerHookInitializer（跨产品单例） |
| 特殊约束 | `launch_config_id`、毕业阈值、狙击税 | 地址后缀 `01`、`tick_spacing`、股票 catalog | 与股票盘字段相近但工厂/hook 不同 | ticker 24h 预留、Airlock 底层、`e18` 后缀只是常见不是硬规则 |
| 创建人 | `deployer` / `tx.from`，可能经 LaunchAndBuy | 事件 `creator` 常是 Token Deployer 合约，**真人**要再解 `tx.from` | 同左 | `LaunchCreated.launcher` = `tx.from`；代币 owner 是 Airlock，**禁止**把协议合约当聪明钱默认匹配 |

混成一个结构体会出现：股票盘 `curve` 永远 NULL、Pons 盘 `pool_id` 开盘时 NULL、Long 的 hook 和 o1 填错还编译通过。v0 用 **四张明细表 + 可选瘦目录**。

### 3.2 瘦目录（建议有）

只存「列表页」需要的键，不存协议细节。源数据仍以四张明细表为准。

`launch_index`

| 字段 | 说明 |
| --- | --- |
| `token_address` | PK，`0x`+40 hex **小写**；`COLLATE NOCASE`，大小写都能查 |
| `category` | `pons` / `o1_stock` / `o1_crypto` / `long` |
| `symbol` / `name` | 展示用 |
| `pair_symbol` | 配对名称：`ETH` / `USDG` / `WYFI` / `AMZN`… |
| `pair_address` | 报价代币；ETH 用 `0x000…000` |
| `creator_eoa` | 签名创建的 EOA（`tx.from`） |
| `creator_contract` | 事件里的 creator/deployer（可能是工厂、Token Deployer、Airlock） |

### 3.7 配对名称怎么填

| 分类 | `pair_symbol` 规则 |
| --- | --- |
| pons | `pair_address==0x0` → `ETH`；USDG 地址 → `USDG`；其它先查本地股票 catalog，未知则存 `UNKNOWN` + 地址 |
| o1_stock | 用 quote 在 o1 股票 catalog 中的代码（AAPL、WYFI…），catalog 缺失则 `UNKNOWN` |
| o1_crypto | `ETH` 或 `USDG` |
| long | 用 `numeraire` 在 `quote_assets` / 股票 catalog 中的 symbol；未知则 `UNKNOWN` |

股票 catalog：v0 优先读链上配置（o1 `quoteConfig`；Long 用 token 元数据），失败再回退静态表。

### 3.8 币对价格更新（单价 U，不是每笔写库）

两条路分开，不要混：

| 口径 | 写哪 | 何时落库 | 用途 |
| --- | --- | --- | --- |
| **成交价（实际价）** | 仅 `wallet_events` | **当场**（聪明钱买卖） | 真实盈亏：数量 ×（卖出价 − 买入价），见 5.3 |
| **展示单价 U** | 仅 `launch_index.price_usd` | **默认每 3 秒**，只 UPDATE 本窗口内 **有成交** 的已监控代币 | 列表给人看 |

规则：

1. **只刷新监控中的、且产生过成交的资产。** 代币必须已在 `launch_index`。窗口内没有任何 `CurveBuy`/`CurveSell`/`Swap`（已知 pool）则 **不写价格行**。不要定时对全市场无成交盘口 `eth_call`。纯创建、没有买卖：`price_usd` 保持空。
2. **内存先记，表后刷。** 扫到成交立刻算出该笔成交单价 U（算法同交易表 exec，不限聪明钱），写入进程内 `token → 最新单价U + 块/tx`，把该 token 标脏。定时器默认 **3 秒**（可配置）把脏集合一次性 UPDATE `launch_index`，价没变则跳过。禁止每条 log 打一次 SQLite。
3. **单位 U。** `price_usd` 是 1 枚 meme 多少美元，人类小数，方便阅读。折算见 4.4。喂价缺失则该次不刷 U（保留上次或空），**禁止写 0**。
4. **不要**把价格再抄到 `launch_pons` 等明细表。
5. Pons 毕业只改 `phase` / `pool_id`；之后成交仍走同一套「内存最新成交 U → 3 秒刷 index」。

链上数量怎么换成「1 枚多少 quote / 多少 U」仍用调研：Pons `06`、o1 `07`、Long `09`、v4 共用 `02`。币对表展示用 **最近一笔监控到的成交单价 U**（窗口内多笔取最后一笔），不用盘口中间价冒充成交价。

实现注意：3 秒刷盘与扫块同进程；脏集合有界；重启后表里仍是上次刷入的 U，要等下一次成交才会再变。

## 4. 需求二：聪明钱包集合

### 4.1 表 `smart_wallets`

一条地址一行。**主键就是地址小写**，没有自增 id。写入前把地址规范成 `0x` + 40 hex 小写；列 `COLLATE NOCASE`，查询大小写都能命中。展示再 checksum。**SQLite 是名单的唯一事实来源**；CSV/SQL/手工 INSERT 都可以，本需求不规定导入工具。**不要** `raw_json` / `extra_json`。

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `address` | TEXT PK `COLLATE NOCASE` | `0x` + 40 hex 小写；允许 EOA **或** Deployer 合约 |
| `display_name` | TEXT | GMGN/Debot/自拟名称 |
| `source` | TEXT | `gmgn` / `debot` / `manual` / `other` |
| `source_url` | TEXT 可空 | 名单出处 |
| `primary_type` | TEXT | 见 4.3，**单主类型** |
| `tags` | TEXT | 逗号分隔：可同时 `launcher,sniper`（不要整段平台原始 JSON） |
| `level` | TEXT | `S` / `A` / `B` / `C` / `D`，由分数切档，可手改（手改后 `level_locked=1`） |
| `score` | REAL | 0–100，见 4.4 |
| `score_win_rate` | REAL 可空 | 计算时快照 |
| `score_profit_usd` | REAL 可空 | **必须是 USD**，不能只留 ETH/USDG 原值当总分 |
| `score_sample_n` | INTEGER | 参与评分的已关闭笔数 |
| `note` | TEXT | 备注 |
| `status` | TEXT | `active` / `paused` / `blacklisted` |
| `level_locked` | INTEGER | `0`/`1`；手改级别后为 1 |
| `created_at` / `updated_at` | TEXT | UTC ISO8601 |
| `last_seen_at` | TEXT 可空 | 最近一次命中发盘/买卖，UTC |

不要把 LongLauncher、Airlock、PoolManager、Universal Router、各工厂默认写进名单。o1 Token Deployer、用户自己的 Deployer 合约 **可以**进名单。

### 4.2 名单热更新（运行中必须感知）

名单会随时被改（sqlite3 / 以后的写接口都行）。监听进程 **禁止**启动时把 `smart_wallets` 读进内存就再也不查库。

| 库里发生了什么 | 扫块侧必须变成 |
| --- | --- |
| 新增一行且 `status=active` | 刷新后，后续块里该地址的发盘/买卖能命中：打中文日志、写 `wallet_events` |
| 已有行改成 `active`（从暂停/拉黑恢复） | 同上，从刷新后的块开始盯；**不回补**刷新前已处理过的块 |
| 删除该行，或 `status` 改为 `paused` / `blacklisted` | 刷新后 **不再** 打聪明钱日志、**不再** 写新的 `wallet_events`、不再更新该地址 `last_seen_at` |
| 改 `display_name` / `tags` 等 | 下次命中日志用新名称；不改历史行 |

约束：

1. **匹配用「当前有效集合」**：`status=active` 的 `address`（小写）。每处理一块之前必须用这份集合（实现：每块 `SELECT`，或内存表 **≤1 秒**从 SQLite 全量刷新后再匹配）。感知延迟上限 **1 秒**。
2. **不回放历史。** 新加的钱包只盯「刷新之后」的块；不加「从 from_block 重扫专门补它」。
3. **已入库流水保留。** 移除/拉黑不删 `wallet_events`，评分仍可看历史；只是不再追加。
4. **SQLite WAL + `busy_timeout`**：允许你在进程跑着时改 `smart_wallets`；扫块仍是事件表的主写。改名单失败打 `[错误]`，不要静默用过期集合太久（刷新失败则沿用上一份并打错误，下一轮再试）。
5. 四类 **新盘全听** 不受名单影响；只影响聪明钱日志和 `wallet_events`。

### 4.3 `primary_type` 枚举

| 值 | 含义 | 典型行为 |
| --- | --- | --- |
| `launcher` | 发盘 | 频繁 `create` / `launchAndBuy` / `createLaunch` |
| `winner` | 常胜 | 买卖多、胜率高、不一定发盘 |

### 4.4 评分算法（必须折 USD）

**先有样本再打分。** `sample_n < 8`：`score` 最高封顶 49（进不了 A/S）。

盈亏必须用交易表里的 **实际成交单价 U + 数量**，按钱包+代币 **FIFO** 现算（公式见 5.3），不要用币对表 3 秒延迟价。跨 quote 先折成 U 再加减。

定义一笔评分样本：一笔 `sell` 按 FIFO 匹配到的已实现盈亏（可吃掉多笔买）。`profit_usd` 用该已实现盈亏之和。

```text
win_rate     = 已实现盈亏>0 的卖出笔数 / 有匹配的卖出笔数   ∈ [0,1]
profit_norm  = tanh(累计已实现盈亏_U / 10_000)       ∈ (-1,1)，亏损为负
size_norm    = tanh(有匹配的卖出笔数 / 40)           ∈ [0,1)
fresh_norm   = 近 14 天有匹配卖出的笔数 / 卖出笔数    ∈ [0,1]

score = 100 * (0.40*win_rate + 0.35*max(profit_norm,0) + 0.15*size_norm + 0.10*fresh_norm)
        - 20 * max(-profit_norm, 0)
score 截断到 [0, 100]
```

级别（`level_locked=0` 时每次重算覆盖）：

| 级别 | 分数 |
| --- | --- |
| S | ≥ 80 |
| A | ≥ 65 |
| B | ≥ 50 |
| C | ≥ 35 |
| D | < 35 |

重算周期：建议每小时或每 100 笔新事件。日志打印 `score` 与 USD 快照。

发盘不算 win_rate 样本；发盘费不计入盈亏。该创建人随后卖出才算交易。

#### 折 USD 规则（v0 必须做；喂价未定）

每笔 `wallet_events` 写入时带 `quote_usd`（可空，但评分只用非空且可信的行）。换算：

| quote 种类 | v0 规则 | 缺口 |
| --- | --- | --- |
| USDG | 先按 1 USD | 脱锚策略未定 |
| ETH / WETH | `amount * eth_usd` | **待实现**稳定预言机 |
| 股票代币 | `amount * stock_usd`（AMZN/MRNA…） | **待实现**每股 USD 源 |
| 未知 quote | 事件仍入库，`quote_usd` 空，**不进评分样本** | 打「类型=错误」或「缺价=是」 |

链上数量先算成交单价（quote），再乘喂价得 **成交单价 U**。没有 eth_usd / 股价时：交易表 `exec_usd_per_token` 空，**不进评分**；币对表该次不刷 `price_usd`。USD 列失败不得写 0。

价格源实现前不要假装有喂价。候选（需另开技术设计）：自建节点 + 链上池、Blockscout `exchange_rate`、第三方行情 API。失败时该笔跳过评分，不得用 0 U 冒充。

### 5.1 何时触发

行首用中文标签，后面是 `键=值`（空格分隔，值里若有空格用双引号包住）：

### 5.3 表 `wallet_events`

全市场买卖不进这张表；只进聪明钱相关。**不要** `raw_json`。

主键 `id` **不是自增**：由区块号、交易下标、日志下标左补零拼接（算法见 7.2）。没有 `log_index` 时按 `0`。同一条链上 log 只写一行；冲突则跳过（幂等）。

| 字段 | 说明 |
| --- | --- |
| `id` | PK，TEXT。`fillZero(block,8) + fillZero(tx_index,4) + fillZero(log_index,4)` |
| `block_number` | INTEGER，参与拼接 |
| `tx_index` | INTEGER，交易在块内下标；缺省 `0` |
| `log_index` | INTEGER，**协议事件**（`CurveBuy`/`Swap`/`LaunchCreated` 等）在收据里的下标，不是 Transfer；缺省 `0` |
| `tx_hash` | TEXT `COLLATE NOCASE`，浏览器跳转用；**不是**主键 |
| `chain_time` / `ingested_at` | 链上时间 vs 入库时间，均为 UTC |
| `wallet_address` | 逻辑关联 `smart_wallets.address`，小写，`COLLATE NOCASE` |
| `kind` | 库内英文：`launch` / `buy` / `sell`（日志写成 发盘/买入/卖出） |
| `category` | `pons` / `o1_stock` / `o1_crypto` / `long` |
| `token_address` | 盘口代币，小写，`COLLATE NOCASE` |
| `direction` | `buy` / `sell` / `launch` |
| `quote_address` / `quote_symbol` | 花/收回的资产；地址小写 |
| `quote_amount_raw` / `quote_decimals` | 最小单位 |
| `quote_usd` | 本笔 1 单位 quote 折 USD，可空 |
| `eth_usd` / `quote_usd_price` | 计价快照（`quote_usd_price` 与 `quote_usd` 同义，DDL 只留一列） |
| `token_amount_raw` / `token_decimals` | 最小单位；盈亏用人类数量 = raw / 10^decimals |
| `exec_quote_per_token` | 本笔实际成交：1 meme 值多少 quote |
| `exec_usd_per_token` | **必填（买卖、喂价可得时）**：本笔实际成交单价 **U**。盈亏只用这一列，不用币对表价 |
| `router` | `curve` / `universal_router` / `gmgn` / `launch_and_buy` / `relay` / `unknown` |

**不要**在交易表再存盘口中间价 / `spot_*` / `sqrt_price_x96`。**不要**单独一张盈亏表：用流水按 FIFO 现算。

查询索引：`(wallet_address, chain_time)`、`(token_address, chain_time)`、`(kind, chain_time)`。`id` 本身按链上顺序可排序。

发盘：库内 `kind=launch`（日志「类型=发盘」），金额可为 0 或 launch fee；`token_address` 指向新币。同时写对应 `launch_*` 表。发盘 `id` 用创建事件那条 log 的 `block + tx_index + log_index`。发盘不进 FIFO。

#### 真实盈亏（FIFO，单位 U）

按 **同一钱包 + 同一代币**，买卖按 `id`（链上顺序）排队：

```text
买：入队一份仓位 (数量, 成交单价U)
卖：从队头扣减，直到卖出数量扣完

已实现盈亏U = Σ 本次匹配数量 × (卖出成交单价U − 该仓买入成交单价U)
```

例：买入 100 份、单价 1 U；卖出 50 份、单价 2 U → 盈亏 = `50 * (2 - 1)` = **50 U**。剩余 50 份成本仍是 1 U。

再卖若匹配多笔买，把各笔 `(卖价 − 该笔买价) × 匹配量` 加总。卖出数量大于持仓：能匹配的部分照算，超出部分打 `[错误]`，不要用 0 成本假造盈利。

`exec_usd_per_token` 为空的行不参与匹配、不进评分。未实现盈亏（用币对表价估剩余仓）v0 不做。

## 7. SQLite 与 Docker

### 7.1 SQLite 约定

- 文件：`/data/robinhood_meme.sqlite3`（容器内），主机挂卷
- WAL、`busy_timeout=5000`、**单 writer**（扫块进程独占写）
- 迁移：线性 SQL 文件 `migrations/001_init.sql`…，启动时执行
- 备份：停写或 `VACUUM INTO`
- 金额一律 **字符串或 INTEGER 最小单位**，不要用 REAL 存 wei；USD 评分可用 REAL
- 时间字段：UTC，`YYYY-MM-DDTHH:MM:SSZ` 或 Unix 秒 + 展示层转 CST
- **禁止**落 `raw_json` / `extra_json` / 原始 receipt blob。列解不出就丢，以后要再加列
- **禁止**无意义自增代理主键。主键规则见 7.2

GORM 能开 SQLite；四meme 是 MySQL 习惯。若用 GORM 必须四个 Launch Model 四张表，禁止一个万能 Model；主键字段关自增。

### 7.2 主键

| 表 | 主键 | 说明 |
| --- | --- | --- |
| `smart_wallets` | `address` | 小写 `0x`+40 hex |
| `wallet_events` | `id` | 区块号 + tx 下标 + log 下标拼接，见下 |
| `launch_index` / `launch_*` | `token_address` | 小写代币地址 |
| `quote_assets` | `address` | 小写报价资产地址 |
| `sync_state` | `name` | 如 `rh_4663`，一行一条链的水位 |

`wallet_events.id` 算法（与用户给定 Java 一致；`log_index` / `tx_index` 缺失当 `0`）：

```text
id = 左补零(block_number, 8) + 左补零(tx_index, 4) + 左补零(log_index, 4)
```

左补零：目标宽度减去十进制位数，前面补 `0`，再拼数字本身。位数 **超过宽度不截断**（串变长）；实现时对超宽打 `[错误]` 日志，仍按不截断写入以免碰撞。

例：块 `51337623`、tx `12`、log `7` → `5133762300120007`。  
例：块 `7887312`、tx `0`、无 log → `0788731200000000`。

Go 侧写成可单测的纯函数（对应用户 Java 的 `calcTxUniqueSeq` / `fillZeroPadding`）。`log_index` 取协议事件在 **transaction receipt** 里的下标。

### 7.3 大小写（表设计不区分，查询都能命中）

SQLite 表名/列名本身大小写不敏感。业务上还要：

- **写入**：地址、`tx_hash`、`pool_id` 一律规范成小写（地址带 `0x`）
- **列**：上述 TEXT 主键与关联列声明 `COLLATE NOCASE`（ASCII 字母，覆盖 hex `A–F`）
- **查询**：HTTP / SQL 传入 `0xAbC…` 或 `0XABC…` 都能命中同一行；应用层仍应先规范化再查
- **不覆盖**：缺 `0x` 前缀不算同一地址，查询层补 `0x` 后再比

不要靠「库里存 checksum 混合大小写」来展示；展示层再 checksum。

### 7.4 Docker（建议）

```text
服务：一个 Go 二进制（go-zero rest + 扫块 goroutine）
挂载：./data → /data
环境：RH_RPC_URL、RH_FROM_BLOCK、LOG_LEVEL、HTTP 端口、PRICE_FLUSH_SEC（默认 3）
不在镜像里塞 RPC 密钥；用 env 或 compose env_file（勿提交）
```

公开 RPC 在调研里会 403，生产用自有节点。健康检查：进程存活 + `sync_state` 落后块数 + go-zero `/health`。

```text
internal/parser/pons|o1stock|o1crypto|long
internal/domain/      四个 Launch 类型、Wallet、Event
internal/store/       SQLite，按表分文件
internal/wallets/     从 SQLite 热加载 active 集合（≤1s / 每块）
internal/score/       评分（U）+ FIFO 已实现盈亏，纯函数可测
internal/price/       成交折 U；内存脏集合；默认 3s 刷 launch_index.price_usd；喂价未定时返回错误而非 0
internal/logx/        中文结构化日志字段
```

扫块与 HTTP 同进程：HTTP 只读；SQLite 单 writer。自动交易不进 v0 目录。

## 9. 数据流与幂等

```text
RPC 块 → 分类 parser → domain 对象
                ↓
        新盘：store 事务 launch_* + launch_index（此时 price_usd 空）
                ↓
        该盘口有成交（不限聪明钱）
                → 按 06/07/09 算成交单价 U，写入内存脏集合（不立刻 UPDATE 币对表）
                ↓
        若地址 ∈ **当前** smart_wallets.active（4.2 热更新）
                → 当场写 wallet_events（数量 + 成交单价 U）+ 中文买卖/发盘日志
                → 卖出按 FIFO 算已实现盈亏 U（可打在日志上）
                → 更新 last_seen_at
                ↓
        每 3s：只把脏代币 UPDATE launch_index.price_usd + [价格] 日志
                →（异步或定时）按 FIFO 盈亏重算 score
```

同一 `wallet_events.id`（区块号+tx_index+log_index 拼接）插入冲突则跳过。新盘 `token_address` 已存在：若 category 一致则忽略；不一致打 `[错误]` 日志，**不覆盖**。

reorg：水位记新 hash，已写入事件保留。可能出现分叉上的「幽灵」行；v0 接受，靠 `wallet_events.id` 主键避免同 log 双写。不要做块高回滚删除。
