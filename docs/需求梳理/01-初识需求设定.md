- 来源清单：

- 状态：第 10 节已拍板；实现前仍缺的是价格源与 DDL，不是产品范围

## 结论先行

v0 做三件事：听新盘、盯聪明钱、从流水里筛优质项目。先发现、先记账，不下单。

1. **新盘入库（四类独立模型）**  
   覆盖：Pons V2、o1 股票配对、o1 加密货币配对、**Long**。每类一张表、一套 Go 结构体。公共信息可以有一张很瘦的目录表，**禁止**把曲线地址、股票 quote、Doppler hook、毕业阈值塞进同一个「万能 Launch」对象。

2. **聪明钱包主数据**  
   一张 `smart_wallets`。**以 SQLite 里的行准**（导入方式不在本需求）。评分必须折 USD。级别由分数切档。名单地址可以是 EOA，也可以是 Deployer 合约。

3. **盯盘流水**  
   集合里 `status=active` 的地址一旦发盘或买入/卖出四类盘口：stdout 打结构化日志，同时写入 `wallet_events`（幂等）。买卖 **只入库聪明钱**，含 GMGN 等多跳。用户地址取实际拿到/交出代币的钱包，不要用 v4 `Swap.sender`。

运行形态：Go 常驻扫块 + **go-zero** 最小只读 HTTP + 本地 SQLite + Docker 挂卷。时间戳一律 UTC。reorg **不回滚**已写入事件。

## 1. 产品目标与非目标

### 1.1 要达成

| 目标 | v0 验收 |
| --- | --- |
| 新盘不漏（四类之内） | 工厂事件出现后，对应类型表有一行，且能回答：分类、配对名称、创建人、创建时间 |
| 聪明钱可运营 | 能增删改查钱包（改 SQLite 即可）；评分可解释；暂停/拉黑立即停止日志与入库 |
| 行为可追溯 | 发盘/买/卖都能在日志和表里对上 tx、合约、方向、金额、折 USD 快照 |
| 帮你找优质项目 | 能列出：聪明钱发的盘、多聪明钱同买、某钱包胜率高的盘（v0 用 SQL / 只读 API，信号表可后做） |

### 1.2 明确不做（v0）

- 自动买入/卖出、跟单下单、私钥热钱包
- Bags、hood.fun、pools.trade、Bankr 等（Long 已纳入；其它仍范围外）
- Debot/GMGN 实时爬虫当主数据源（可作名单出处标签；链上事件才是事实）
- 钱包 CSV/API 导入方案（不限定、本文件不设计）
- 多链、回测 UI、对外公网鉴权产品
- reorg 回滚 SQLite

### 1.3 成功长什么样

```text
[新盘] 08:01:02Z long token=0x4d41…e18 pair=AMZN creator=0x8130… name=SENDER
[聪明钱-发盘] 08:01:02Z wallet=0x8130… → long SENDER
[聪明钱-买] 08:01:08Z wallet=0xgmgn… buy SENDER quote=… AMZN quote_usd=… tx=0x…
```

同一笔链上事实：日志一份、SQLite 一份，重启不丢、重扫不重复。

## 2. 监控范围（四类盘口）

分类 **只由创建交易打到的工厂/入口决定**，不用 Debot 猫标、不用代币名字猜测。

| 分类代码 | 含义 | 链上入口（调研已核） | 配对长什么样 |
| --- | --- | --- | --- |
| `pons` | Pons V2 内盘曲线，可毕业进 v4 | Factory `0x7eD598Bc…EC7e` 的 `TokenLaunched`；前端常打 LaunchAndBuy `0xe33E9E47…2948` | quote = **ETH `0x0` 或 USDG**，以后还可能是股票 token |
| `o1_stock` | o1 股票配对，创建即 v4 + LaunchHook | Factory `0xe64AC411…F297` 的 `Launched` | quote = **已注册股票代币**（如 WYFI）；代币地址以 `01` 结尾 |
| `o1_crypto` | o1 加密货币配对 | Factory `0x411F2128…0Ba5` 的 `Launched` | quote = **ETH 或 USDG**；Hook 与股票盘 **不是同一个** |
| `long` | LongLauncher → Doppler Airlock，创建即 v4 | LongLauncher `0x22e99278…eeED` 的 `LaunchCreated` | quote = `numeraire`（已核样本为股票代币 AMZN/MRNA）；**不要**把全部 Airlock `Create` 算 Long |

监听骨架（实现时按调研拆 adapter，不要一个 parser 写四类 ABI）：

```text
eth_getBlockReceipts / 日志订阅
        ├── Pons TokenLaunched / CurveBuy / CurveSell / PoolGraduated
        ├── Long LaunchCreated + PoolManager.Swap（poolId ∈ launch_long）
        ├── o1_stock Launched + PoolManager.Swap（hooks=股票 LaunchHook）
        └── o1_crypto Launched + PoolManager.Swap（hooks=加密 LaunchHook）
```

新盘四类全听。Pons 毕业事件要听（更新 `phase`），但毕业后全市场 Swap 仍不入库。买卖只入库聪明钱相关。

## 3. 需求一：新盘基本信息入库（独立类型）

### 3.1 为什么不能一张「Launch」宽表

| | Pons | o1 股票 | o1 加密 | Long |
| --- | --- | --- | --- | --- |
| 内盘曲线 | 每币一个 `curve` | 无 | 无 | 无 |
| 报价资产 | ETH / USDG /（可能）股票 | 股票代币 | ETH / USDG | `numeraire`（已核为股票） |
| 池身份 | 毕业后才有 v4 pool | 创建即有 `pool_id` | 创建即有 `pool_id` | 创建即有 `pool_id` |
| Hook | 毕业后才是 Pons meme hook | 股票 LaunchHook | 另一套 LaunchHook | DopplerHookInitializer（跨产品单例） |
| 特殊约束 | `launch_config_id`、毕业阈值、狙击税 | 地址后缀 `01`、`tick_spacing`、股票 catalog | 与股票盘字段相近但工厂/hook 不同 | ticker 24h 预留、Airlock 底层、`e18` 后缀只是常见不是硬规则 |
| 创建人 | `deployer` / `tx.from`，可能经 LaunchAndBuy | 事件 `creator` 常是 Token Deployer 合约，**真人**要再解 `tx.from` | 同左 | `LaunchCreated.launcher` = `tx.from`；代币 owner 是 Airlock，**禁止**把协议合约当聪明钱默认匹配 |

混成一个结构体会出现：股票盘 `curve` 永远 NULL、Pons 盘 `pool_id` 开盘时 NULL、Long 的 hook 和 o1 填错还编译通过。v0 用 **四张明细表 + 可选瘦目录**。

### 3.2 瘦目录（建议有）

只存「列表页」需要的键，不存协议细节。源数据仍以四张明细表为准。

`launch_index`

| 字段 | 说明 |
| --- | --- |
| `token_address` | PK，小写 |
| `category` | `pons` / `o1_stock` / `o1_crypto` / `long` |
| `symbol` / `name` | 展示用 |
| `pair_symbol` | 配对名称：`ETH` / `USDG` / `WYFI` / `AMZN`… |
| `pair_address` | 报价代币；ETH 用 `0x000…000` |
| `creator_eoa` | 签名创建的 EOA（`tx.from`） |
| `creator_contract` | 事件里的 creator/deployer（可能是工厂、Token Deployer、Airlock） |
| `created_at` | 链上块时间，**UTC**（`YYYY-MM-DDTHH:MM:SSZ`） |
| `block_number` / `tx_hash` | 创建交易 |
| `status` | `active` / `graduated`（仅 pons 有意义）/ `ignored` |

### 3.3 类型 A：`launch_pons`

| 字段 | 说明 |
| --- | --- |
| `token_address` | PK |
| `symbol` / `name` / `logo` / `description` | TokenParams 能解则存 |

### 3.5 类型 C：`launch_o1_crypto`

与股票盘 **同构但分表**：`quote` 只有 ETH/USDG；`hooks` 必须是加密 LaunchHook；**没有** `01` 后缀硬规则。不要复用 `launch_o1_stock` 结构体。

### 3.6 类型 D：`launch_long`

依据 `docs/调研/09-Long解析与交易.md`。发现只认 LongLauncher，不认裸 Airlock。

| 字段 | 说明 |
| --- | --- |
| `token_address` | PK（常见 `e18` 结尾，**不校验、不拒绝**） |
| `symbol` / `name` | `normalizedTicker` / token 名 |
| `quote_address` / `quote_symbol` | `LaunchCreated.numeraire`；未知则 `UNKNOWN` + 地址 |
| `quote_decimals` | 读 ERC-20 `decimals`，失败再查 `quote_assets` |
| `pool_id` | 同笔 `Initialize.id` |
| `fee` / `tick_spacing` / `hooks` | 来自 `Initialize`；样本为动态费 `8388608`、`tickSpacing=8`、hooks=`DopplerHookInitializer` |
| `ticker_key` | `LaunchCreated.tickerKey` |
| `deployed_at` / `reserved_until` | 事件 uint48，转 UTC 文本；预留窗口 24h |
| `pool_initializer` | 样本为 DopplerHookInitializer |
| `launcher` | `LaunchCreated.launcher` |
| `creator_eoa` | `tx.from`（样本与 launcher 相同） |
| `integrator` | create 参数；样本为 EOA `0x92d435…` |
| `airlock` | 常量 `0xeb7C0347…0862`，冗余便于审计 |
| `initial_supply` / `num_tokens_to_sell` | create 参数能解则存 |
| `block_number` / `tx_hash` / `log_index` / `created_at` | 链坐标 |

Go 侧四个 struct：`PonsLaunch`、`O1StockLaunch`、`O1CryptoLaunch`、`LongLaunch`，parser 按工厂分流。禁止 `map[string]any` 当主模型。

### 3.7 配对名称怎么填

| 分类 | `pair_symbol` 规则 |
| --- | --- |
| pons | `pair_address==0x0` → `ETH`；USDG 地址 → `USDG`；其它先查本地股票 catalog，未知则存 `UNKNOWN` + 地址 |
| o1_stock | 用 quote 在 o1 股票 catalog 中的代码（AAPL、WYFI…），catalog 缺失则 `UNKNOWN` |
| o1_crypto | `ETH` 或 `USDG` |
| long | 用 `numeraire` 在 `quote_assets` / 股票 catalog 中的 symbol；未知则 `UNKNOWN` |

股票 catalog：v0 优先读链上配置（o1 `quoteConfig`；Long 用 token 元数据），失败再回退静态表。

## 4. 需求二：聪明钱包集合

### 4.1 表 `smart_wallets`

一条地址一行。地址统一小写存；展示再 checksum。**SQLite 是名单的唯一事实来源**；CSV/SQL/手工 INSERT 都可以，本需求不规定导入工具。

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增 |
| `address` | TEXT UNIQUE | `0x` + 40 hex 小写；允许 EOA **或** Deployer 合约 |
| `display_name` | TEXT | GMGN/Debot/自拟名称 |
| `source` | TEXT | `gmgn` / `debot` / `manual` / `other` |
| `source_url` | TEXT 可空 | 名单出处 |
| `primary_type` | TEXT | 见 4.2，**单主类型** |
| `tags` | TEXT | 逗号或 JSON 数组：可同时 `launcher,sniper` |
| `level` | TEXT | `S` / `A` / `B` / `C` / `D`，由分数切档，可手改（手改后 `level_locked=1`） |
| `score` | REAL | 0–100，见 4.3 |
| `score_win_rate` | REAL 可空 | 计算时快照 |
| `score_profit_usd` | REAL 可空 | **必须是 USD**，不能只留 ETH/USDG 原值当总分 |
| `score_sample_n` | INTEGER | 参与评分的已关闭笔数 |
| `note` | TEXT | 备注 |
| `status` | TEXT | `active` / `paused` / `blacklisted` |
| `created_at` / `updated_at` | TEXT | UTC ISO8601 |
| `last_seen_at` | TEXT 可空 | 最近一次命中发盘/买卖，UTC |
| `extra_json` | TEXT | 平台原始字段 |

不要把 LongLauncher、Airlock、PoolManager、Universal Router、各工厂默认写进名单。o1 Token Deployer、用户自己的 Deployer 合约 **可以**进名单。

### 4.2 `primary_type` 枚举

| 值 | 含义 | 典型行为 |
| --- | --- | --- |
| `launcher` | 发盘 | 频繁 `create` / `launchAndBuy` / `createLaunch` |
| `winner` | 常胜 | 买卖多、胜率高、不一定发盘 |
| `sniper` | 开盘枪 | 创建后数秒内买 |
| `follower` | 跟风 | 总在其它聪明钱之后买 |
| `kol` | 公开 KOL | 来源标注为主 |
| `unknown` | 未分类 | 默认 |

一个地址既发盘又常胜：`primary_type=launcher`，`tags` 含 `winner`。

### 4.3 评分算法（必须折 USD）

**先有样本再打分。** `sample_n < 8`：`score` 最高封顶 49（进不了 A/S）。

定义一笔「已关闭交易」：同一钱包对同一 `token_address`，存在买入后又出现卖出（或持仓归零）。跨 quote 资产的盈亏 **先折成 USD 再加减**，禁止按 ETH/USDG/股票分桶当总分。

```text
win_rate     = 盈利闭环笔数 / 闭环笔数          ∈ [0,1]
profit_norm  = tanh(累计盈利_USD / 10_000)       ∈ (-1,1)，亏损为负
size_norm    = tanh(闭环笔数 / 40)               ∈ [0,1)
fresh_norm   = 近 14 天有成交的闭环 / 闭环笔数    ∈ [0,1]

score = 100 * (0.40*win_rate + 0.35*max(profit_norm,0) + 0.15*size_norm + 0.10*fresh_norm)
        - 20 * max(-profit_norm, 0)
score 截断到 [0, 100]
```

级别（`level_locked=0` 时每次重算覆盖）：

| 级别 | 分数 |
| --- | --- |
| S | ≥ 80 |
| A | ≥ 65 |
| B | ≥ 50 |
| C | ≥ 35 |
| D | < 35 |

重算周期：建议每小时或每 100 笔新事件。日志打印 `score` 与 USD 快照。

发盘不算 win_rate 样本；发盘费不计入盈亏。该创建人随后卖出才算交易。

#### 折 USD 规则（v0 必须做；喂价未定）

每笔 `wallet_events` 写入时带 `quote_usd`（可空，但评分只用非空且可信的行）。换算：

| quote 种类 | v0 规则 | 缺口 |
| --- | --- | --- |
| USDG | 先按 1 USD | 脱锚策略未定 |
| ETH / WETH | `amount * eth_usd` | **待实现**稳定预言机 |
| 股票代币 | `amount * stock_usd`（AMZN/MRNA…） | **待实现**每股 USD 源 |
| 未知 quote | 事件仍入库，`quote_usd` 空，**不进评分样本** | 打 `kind=error` 或 `price_missing=1` |

价格源实现前不要假装有喂价。候选（需另开技术设计）：自建节点 + 链上池、Blockscout `exchange_rate`、第三方行情 API。失败时该笔跳过评分，不得用 0 USD 冒充。

## 5. 需求三：发盘 / 买卖日志 + 交易表

### 5.1 何时触发

仅当 `smart_wallets.status=active` 且地址匹配：

| 事件 | 匹配谁 | 方向 |
| --- | --- | --- |
| 四类工厂创建 | `creator_eoa`（`tx.from`）**或** 名单中的 Deployer/creator 合约 | `launch` |
| Pons `CurveBuy` / `CurveSell` | **`recipient`（买）/ 卖侧对应 recipient** | `buy` / `sell` |
| o1 / Long `PoolManager.Swap` | 本交易里 meme `Transfer` 的 `to`（买）或 `from`（卖） | `buy` / `sell` |

GMGN 聚合器（`0x65050A9b…40Dc` 等）多跳 **要入库**：仍用 Transfer 归因，`router` 标 `gmgn`。Relay 等其它聚合器同样记，`router` 用能识别的名字或 `unknown`。

Router、LaunchAndBuy、PoolManager、LongLauncher、Airlock **不要**当成用户钱包写入事件；除非该地址被你显式放进 `smart_wallets`（不建议放协议合约）。

### 5.2 日志（stdout，必须结构化）

```text
time=2026-09-01T08:01:08Z kind=buy category=long token=0x4d41… wallet=0xabc… wallet_name=gmgn:foo direction=buy quote_symbol=AMZN quote_amount=... quote_usd=... token_amount=... tx=0x… block=123 score=72 level=A chain_time=2026-09-01T08:01:07Z
```

`kind`：`launch` / `buy` / `sell`。  
`time`：本机处理时间（UTC）**和** 链上块时间（`chain_time=`，UTC）。

失败解析打 `kind=error`，不要静默丢弃。

### 5.3 表 `wallet_events`

全市场买卖不进这张表；只进聪明钱相关。

| 字段 | 说明 |
| --- | --- |
| `id` | PK |
| `tx_hash` + `log_index` | UNIQUE，幂等 |
| `block_number` / `chain_time` / `ingested_at` | 链上时间 vs 入库时间，均为 UTC |
| `wallet_address` | 逻辑关联 `smart_wallets.address` |
| `kind` | `launch` / `buy` / `sell` |
| `category` | `pons` / `o1_stock` / `o1_crypto` / `long` |
| `token_address` | 盘口代币 |
| `direction` | `buy` / `sell` / `launch` |
| `quote_address` / `quote_symbol` | 花/收回的资产 |
| `quote_amount_raw` / `quote_decimals` | 最小单位 |
| `quote_usd` | 折 USD，可空 |
| `eth_usd` / `quote_usd_price` | 计价快照，便于复盘 |
| `token_amount_raw` / `token_decimals` | 最小单位 |
| `price_quote_per_token` | 可选 |
| `router` | `curve` / `universal_router` / `gmgn` / `launch_and_buy` / `relay` / `unknown` |
| `raw_json` | 原始 log 摘要 |

查询索引：`(wallet_address, chain_time)`、`(token_address, chain_time)`、`(kind, chain_time)`。

发盘：`kind=launch`，金额可为 0 或 launch fee；`token_address` 指向新币。同时写对应 `launch_*` 表。

## 7. SQLite 与 Docker

### 7.1 SQLite 约定

- 文件：`/data/robinhood_meme.sqlite3`（容器内），主机挂卷
- WAL、`busy_timeout=5000`、**单 writer**（扫块进程独占写）
- 迁移：线性 SQL 文件 `migrations/001_init.sql`…，启动时执行
- 备份：停写或 `VACUUM INTO`
- 金额一律 **字符串或 INTEGER 最小单位**，不要用 REAL 存 wei；USD 评分可用 REAL
- 时间字段：UTC，`YYYY-MM-DDTHH:MM:SSZ` 或 Unix 秒 + 展示层转 CST

GORM 能开 SQLite；四meme 是 MySQL 习惯。若用 GORM 必须四个 Launch Model 四张表，禁止一个万能 Model。

### 7.2 Docker（建议）

```text
服务：一个 Go 二进制（go-zero rest + 扫块 goroutine）
挂载：./data → /data
环境：RH_RPC_URL、RH_FROM_BLOCK、LOG_LEVEL、HTTP 端口
不在镜像里塞 RPC 密钥；用 env 或 compose env_file（勿提交）
```

公开 RPC 在调研里会 403，生产用自有节点。健康检查：进程存活 + `sync_state` 落后块数 + go-zero `/health`。

## 8. Go 框架（已选 go-zero）

对照仓库 `go_fourmeme_v3`：go-zero + GORM + MySQL。本项目是 **链上 worker + SQLite + 只读 API**，用 go-zero 方便以后加写接口和管理端，v0 不要把 fourmeme 的 MySQL/下单模块搬过来。

```text
cmd/ 或 go-zero 生成的 rest 入口
internal/chain/       RPC、收据、水位
internal/parser/pons|o1stock|o1crypto|long
internal/domain/      四个 Launch 类型、Wallet、Event
internal/store/       SQLite，按表分文件
internal/score/       评分（USD），纯函数可测
internal/price/       折 USD；喂价未定时返回错误而非 0
internal/logx/        结构化日志字段
```

扫块与 HTTP 同进程：HTTP 只读；SQLite 单 writer。自动交易不进 v0 目录。

## 9. 数据流与幂等

```text
RPC 块 → 分类 parser → domain 对象
                ↓
        store 事务：launch_* + launch_index
                ↓
        若地址 ∈ smart_wallets.active
                → 日志 + wallet_events（含 GMGN 多跳）
                → 更新 last_seen_at
                →（异步或定时）按 USD 重算 score
```

同一 `tx_hash+log_index` 插入冲突则跳过。新盘 `token_address` 已存在：若 category 一致则忽略；不一致打 `error` 日志，**不覆盖**。

reorg：水位记新 hash，已写入事件保留。可能出现分叉上的「幽灵」行；v0 接受，靠 UNIQUE 避免同 log 双写。不要做块高回滚删除。
