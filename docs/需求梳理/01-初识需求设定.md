# 01 初识需求设定（v0 暂定）

- 最新更新时间：2026-09-01 17:20 (UTC+8)
- 适用范围：Robinhood Chain（chainId `4663`）监听服务的第一版产品边界；**不含自动买卖**
- 来源清单：
  - 用户 2026-09-01 口述：监控 Pons / o1 股票配对 / o1 加密货币配对；新盘入库；聪明钱包表；发盘与买卖日志+交易表；SQLite；Docker；Go
  - 本地调研：`docs/调研/04-监听与交易方案.md`、`06-Pons-V2解析与交易.md`、`07-o1exchange-RWA解析与交易.md`
- 状态：初版草稿，供你阅读后改口径；标了 **待确认** 的不要当已拍板

## 结论先行

v0 做三件事，目标是 **听新盘、盯聪明钱、从流水里筛优质项目**，先发现、先记账，不下单。

1. **新盘入库（三类独立模型）**  
   只覆盖：Pons V2、o1 股票配对、o1 加密货币配对。每类一张表、一套 Go 结构体。公共信息（代币地址、创建交易、块高、时间）可以有一张很瘦的目录表，**禁止**把曲线地址、股票 quote、毕业阈值塞进同一个「万能 Launch」对象。

2. **聪明钱包主数据**  
   一张 `smart_wallets`。人工/导入为主；评分用「胜率 + 盈利规模 + 样本数」可复现公式，级别由分数切档。

3. **盯盘流水**  
   集合里的地址一旦 **发盘** 或 **买入/卖出** 三类盘口：stdout 打结构化日志，同时写入 `wallet_events`（幂等）。用户地址取 **实际拿到/交出代币的钱包**，不要用 v4 `Swap.sender`（那是 Router）。

运行形态：Go 常驻进程 + 本地 SQLite + Docker 挂卷。v0 可以没有 HTTP；框架见第 8 节，**建议先 worker，不要先上 go-zero 全家桶**。

## 1. 产品目标与非目标

### 1.1 要达成

| 目标 | v0 验收 |
| --- | --- |
| 新盘不漏（三类之内） | 工厂事件出现后，对应类型表有一行，且能回答：分类、配对名称、创建人、创建时间 |
| 聪明钱可运营 | 能增删改查钱包；评分可解释；暂停/拉黑立即停止日志与入库 |
| 行为可追溯 | 发盘/买/卖都能在日志和表里对上 tx、合约、方向、金额 |
| 帮你找优质项目 | 能列出：聪明钱发的盘、多聪明钱同买、某钱包胜率高的盘（见 6.3，v0 用查询/日志即可） |

### 1.2 明确不做（v0）

- 自动买入/卖出、跟单下单、私钥热钱包
- Pons 以外的发射台（Long、Bags、hood.fun、pools.trade…）— 调研里它们有量，但本版范围外
- Debot/GMGN 实时爬虫当主数据源（可作 **导入聪明钱名单** 的来源标签，链上事件才是事实）
- 多链、回测 UI、对外 API 鉴权

### 1.3 成功长什么样（给你后续改需求时对照）

```text
[新盘] 16:01:02 pons token=0x4d3a…0466 pair=USDG creator=0xabc… name=Chair
[聪明钱-发盘] 16:01:02 wallet=0xgmgn… → pons Chair
[聪明钱-买] 16:01:08 wallet=0xgmgn… buy Chair quote=470.08 USDG tx=0x063b…
```

同一笔链上事实：日志一份、SQLite 一份，重启不丢、重扫不重复。

## 2. 监控范围（三类盘口）

分类 **只由创建交易打到的工厂/入口决定**，不用 Debot 猫标、不用代币名字猜测。

| 分类代码 | 含义 | 链上入口（调研已核） | 配对长什么样 |
| --- | --- | --- | --- |
| `pons` | Pons V2 内盘曲线，可毕业进 v4 | Factory `0x7eD598Bc…EC7e` 的 `TokenLaunched`；前端常打 LaunchAndBuy `0xe33E9E47…2948` | quote = **ETH `0x0` 或 USDG**，以后还可能是股票 token |
| `o1_stock` | o1 股票配对，创建即 v4 + LaunchHook | Factory `0xe64AC411…F297` 的 `Launched` | quote = **已注册股票代币**（如 WYFI）；代币地址以 `01` 结尾 |
| `o1_crypto` | o1 加密货币配对 | Factory `0x411F2128…0Ba5` 的 `Launched` | quote = **ETH 或 USDG**；Hook 与股票盘 **不是同一个** |

监听骨架（实现时按调研拆 adapter，不要一个 parser 写三类 ABI）：

```text
eth_getBlockReceipts / 日志订阅
        ├── Pons TokenLaunched / CurveBuy / CurveSell / PoolGraduated
        ├── o1_stock Launched + PoolManager.Swap（hooks=股票 LaunchHook）
        └── o1_crypto Launched + PoolManager.Swap（hooks=加密 LaunchHook）
```

**待确认：** v0 是否监听 Pons **毕业**（`PoolGraduated`）和曲线买卖（全体盘口 vs 仅聪明钱相关）。建议：新盘三类全听；**买卖只入库聪明钱相关**，避免 SQLite 被全市场 CurveBuy 打爆。

## 3. 需求一：新盘基本信息入库（独立类型）

### 3.1 为什么不能一张「Launch」宽表

| | Pons | o1 股票 | o1 加密 |
| --- | --- | --- | --- |
| 内盘曲线 | 每币一个 `curve` | 无 | 无 |
| 报价资产 | ETH / USDG /（可能）股票 | 股票代币 | ETH / USDG |
| 池身份 | 毕业后才有 v4 pool | 创建即有 `pool_id` | 创建即有 `pool_id` |
| Hook | 毕业后才是 Pons meme hook | 股票 LaunchHook | 另一套 LaunchHook |
| 特殊约束 | `launch_config_id`、毕业阈值、狙击税 | 地址后缀 `01`、`tick_spacing`、股票 catalog | 与股票盘字段相近但工厂/hook 不同 |
| 创建人 | `deployer` / `tx.from`，可能经 LaunchAndBuy | 事件 `creator` 常是 Token Deployer 合约，**真人**要再解 `tx.from` | 同左 |

混成一个结构体会出现：股票盘 `curve` 永远 NULL、Pons 盘 `pool_id` 开盘时 NULL、加密盘和股票盘 Hook 填错还编译通过。v0 用 **三张明细表 + 可选瘦目录**。

### 3.2 瘦目录（可选，建议有）

只存「列表页」需要的键，不存协议细节。源数据仍以三张明细表为准。

`launch_index`

| 字段 | 说明 |
| --- | --- |
| `token_address` | PK，小写 |
| `category` | `pons` / `o1_stock` / `o1_crypto` |
| `symbol` / `name` | 展示用 |
| `pair_symbol` | 配对名称：`ETH` / `USDG` / `WYFI` / `AAPL`… |
| `pair_address` | 报价代币；ETH 用 `0x000…000` |
| `creator_eoa` | 签名创建的 EOA（`tx.from`） |
| `creator_contract` | 事件里的 creator/deployer（可能是工厂或 Deployer） |
| `created_at` | 链上时间（块时间） |
| `block_number` / `tx_hash` | 创建交易 |
| `status` | `active` / `graduated`（仅 pons 有意义）/ `ignored` |

### 3.3 类型 A：`launch_pons`

| 字段 | 说明 |
| --- | --- |
| `token_address` | PK |
| `symbol` / `name` / `logo` / `description` | TokenParams 能解则存 |
| `curve_address` | 内盘买卖目标 |
| `pair_address` / `pair_symbol` | ETH 或 USDG 或其它已批准 quote |
| `pair_decimals` | ETH 18，USDG 6 |
| `launch_config_id` | 供应/费率/毕业阈值套餐 |
| `graduation_threshold` | quote 数量，最小单位 |
| `deployer` | 事件 deployer |
| `creator_eoa` | `tx.from` |
| `creator_fee_recipient` | 若能从 params 解出 |
| `launch_entry` | `factory` 或 `launch_and_buy` |
| `first_buy_quote` / `first_buy_tokens` | 仅 launchAndBuy 同笔首买 |
| `phase` | `curve` / `graduated` / `failed` |
| `graduated_at` / `pool_id` | 毕业后补；未毕业为空 |
| `block_number` / `tx_hash` / `log_index` / `created_at` | 链坐标 |
| `raw_json` | 解不进列的 ABI 余量，便于以后加列 |

唯一约束：`token_address`；`tx_hash+log_index` 防重放。

### 3.4 类型 B：`launch_o1_stock`

| 字段 | 说明 |
| --- | --- |
| `token_address` | PK，校验后缀 `01`，不符记 `anomaly=1` 仍入库并打日志 |
| `symbol` / `name` / `contract_uri` | LaunchParams |
| `quote_address` / `quote_symbol` | 股票代币，**配对名称以股票 symbol 为准** |
| `quote_decimals` | 调研里 Robinhood 股票多为 18 |
| `pool_id` | bytes32 hex |
| `tick_spacing` / `hooks` | 必须是股票 LaunchHook |
| `supply` | 事件 supply |
| `creator_eoa` | `tx.from`（跟单「谁发的」用这个） |
| `creator_event` | `Launched.creator`（常为 Deployer 合约） |
| `native_launch_fee_wei` | `msg.value` |
| `block_number` / `tx_hash` / `log_index` / `created_at` | 链坐标 |
| `raw_json` | 同上 |

### 3.5 类型 C：`launch_o1_crypto`

与股票盘 **同构但分表**：`quote` 只有 ETH/USDG；`hooks` 必须是加密 LaunchHook；**没有** `01` 后缀硬规则（以官方 ABI 为准）。不要复用 `launch_o1_stock` 结构体，避免以后股票特有字段污染加密盘。

Go 侧对应三个 struct：`PonsLaunch`、`O1StockLaunch`、`O1CryptoLaunch`，parser 包按工厂分流。禁止 `map[string]any` 当主模型。

### 3.6 配对名称怎么填

| 分类 | `pair_symbol` 规则 |
| --- | --- |
| pons | `pair_address==0x0` → `ETH`；USDG 地址 → `USDG`；其它先查本地股票 catalog，未知则存 `UNKNOWN` + 地址 |
| o1_stock | 用 quote 在 o1 股票 catalog 中的代码（AAPL、WYFI…），catalog 缺失则 `UNKNOWN` |
| o1_crypto | `ETH` 或 `USDG` |

**待确认：** 股票 catalog 是启动时写死调研表，还是运行时读工厂 `quoteConfig`。建议 v0 读链上 `quoteConfig`，失败再回退静态表。

## 4. 需求二：聪明钱包集合

### 4.1 表 `smart_wallets`

一条钱包一行。地址统一小写存；展示再 checksum。

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增 |
| `address` | TEXT UNIQUE | `0x` + 40 hex 小写 |
| `display_name` | TEXT | GMGN/Debot/自拟名称，如 `gmgn:whales_xx` |
| `source` | TEXT | `gmgn` / `debot` / `manual` / `other` |
| `source_url` | TEXT 可空 | 名单出处，方便你回看 |
| `primary_type` | TEXT | 见 4.2，**单主类型** |
| `tags` | TEXT | 逗号或 JSON 数组：可同时 `launcher,sniper` |
| `level` | TEXT | `S` / `A` / `B` / `C` / `D`，由分数切档，可手改（手改后 `level_locked=1`） |
| `score` | REAL | 0–100，见 4.3 |
| `score_win_rate` | REAL 可空 | 计算时快照 |
| `score_profit_usd` | REAL 可空 | 计算时快照；v0 可先空，用 quote 原值估算 |
| `score_sample_n` | INTEGER | 参与评分的已关闭笔数 |
| `note` | TEXT | 备注 |
| `status` | TEXT | `active` / `paused` / `blacklisted` |
| `created_at` / `updated_at` | TEXT | ISO8601 CST 或 UTC，全库统一 **待确认** |
| `last_seen_at` | TEXT 可空 | 最近一次命中发盘/买卖 |
| `extra_json` | TEXT | 平台原始字段 |

导入：v0 CSV / SQL 种子即可。不强制对接 GMGN API（无 key 时不要阻塞监听）。

### 4.2 `primary_type` 枚举（可改）

| 值 | 含义 | 典型行为 |
| --- | --- | --- |
| `launcher` | 发盘 | 频繁 `create` / `launchAndBuy` / `createLaunch` |
| `winner` | 常胜 | 买卖多、胜率高、不一定发盘 |
| `sniper` | 开盘枪 | 创建后数秒内买 |
| `follower` | 跟风 | 总在其它聪明钱之后买 |
| `kol` | 公开 KOL | 来源标注为主 |
| `unknown` | 未分类 | 默认 |

一个地址既发盘又常胜：`primary_type=launcher`，`tags` 含 `winner`。

### 4.3 评分算法（初稿，可替换）

**先有样本再打分。** `sample_n < 8`：`score` 最高封顶 49（进不了 A/S），避免 2 笔全赢变成 S。

定义一笔「已关闭交易」：同一钱包对同一 `token_address`，存在买入后又出现卖出（或持仓归零）。v0 若不好做闭环，允许退化：**用已实现 quote 盈亏近似**（卖出 quote 累计 − 买入 quote 累计，需同一 quote 资产）。跨 ETH/USDG/股票的盈亏 **待确认** 是否统一折 USD（v0 建议 **按 quote 分桶评分**，总分取交易笔数加权平均）。

```text
win_rate     = 盈利闭环笔数 / 闭环笔数          ∈ [0,1]
profit_norm  = tanh(累计盈利_USD / 10_000)       ∈ (-1,1)，亏损为负
size_norm    = tanh(闭环笔数 / 40)               ∈ [0,1)
fresh_norm   = 近 14 天有成交的闭环 / 闭环笔数    ∈ [0,1]

score = 100 * (0.40*win_rate + 0.35*max(profit_norm,0) + 0.15*size_norm + 0.10*fresh_norm)
        - 20 * max(-profit_norm, 0)             # 净亏损额外扣分
score 截断到 [0, 100]
```

级别（`level_locked=0` 时每次重算覆盖）：

| 级别 | 分数 |
| --- | --- |
| S | ≥ 80 |
| A | ≥ 65 |
| B | ≥ 50 |
| C | ≥ 35 |
| D | < 35 |

重算周期：**待确认**，建议每小时或每 100 笔新事件。日志里打印 `score` 与三项快照，方便你改权重。

**待确认：** 发盘算不算「盈利样本」？建议发盘单独看 `launcher` 类型，**不要把发盘费计入 win_rate**，只把该创建人随后卖出算交易。

## 5. 需求三：发盘 / 买卖日志 + 交易表

### 5.1 何时触发

仅当 `smart_wallets.status=active` 且地址匹配：

| 事件 | 匹配谁 | 方向 |
| --- | --- | --- |
| 三类工厂创建 | `creator_eoa` 或（可选）`deployer` | `launch` |
| Pons `CurveBuy` / `CurveSell` | **`recipient`（买）/ `seller` 对应 recipient（卖）** | `buy` / `sell` |
| o1 `PoolManager.Swap` | 本交易里 meme `Transfer` 的 `to`（买）或 `from`（卖） | `buy` / `sell` |

Router、LaunchAndBuy 合约、PoolManager **不要**写入聪明钱地址。

**待确认：** 聪明钱通过 GMGN 聚合器多跳买入，是否也要记。建议 v0 **记**，用 Transfer 归因，`router` 字段标 `gmgn` / `universal_router` / `curve`。

### 5.2 日志（stdout，必须结构化）

一行一件事，便于 `docker logs` / 采集。建议 logfmt 或 JSON，字段固定：

```text
time=2026-09-01T16:01:08+08:00 kind=buy category=pons token=0x4d3a… wallet=0xabc… wallet_name=gmgn:foo direction=buy quote_symbol=USDG quote_amount=470.080366 token_amount=... tx=0x063b… block=123 score=72 level=A
```

`kind`：`launch` / `buy` / `sell`。  
`time`：本机处理时间 **和** 链上块时间都打（`chain_time=`）。

失败解析打 `kind=error`，不要静默丢弃。

### 5.3 表 `wallet_events`

全市场买卖不进这张表；只进聪明钱相关。

| 字段 | 说明 |
| --- | --- |
| `id` | PK |
| `tx_hash` + `log_index` | UNIQUE，幂等 |
| `block_number` / `chain_time` / `ingested_at` | 链上时间 vs 入库时间 |
| `wallet_address` | FK 逻辑关联 `smart_wallets.address` |
| `kind` | `launch` / `buy` / `sell` |
| `category` | `pons` / `o1_stock` / `o1_crypto` |
| `token_address` | 盘口代币 |
| `direction` | `buy` / `sell` / `launch`（launch 时 direction 可与 kind 相同） |
| `quote_address` / `quote_symbol` | 花/收回的资产 |
| `quote_amount_raw` / `quote_decimals` | 最小单位 |
| `token_amount_raw` / `token_decimals` | 最小单位 |
| `price_quote_per_token` | 可选，解析时能算则写 |
| `router` | `curve` / `universal_router` / `gmgn` / `launch_and_buy` / `unknown` |
| `related_launch_category` | 冗余 category，方便查 |
| `raw_json` | 原始 log 摘要 |

查询索引：`(wallet_address, chain_time)`、`(token_address, chain_time)`、`(kind, chain_time)`。

发盘：`kind=launch`，金额可为 0 或 launch fee；`token_address` 指向新币。同时写对应 `launch_*` 表。

## 6. 丰富项（建议进 v0 / 明确推迟）

### 6.1 建议进 v0（仍是发现，不是交易）

- **扫块水位表** `sync_state`（`last_block`、`last_hash`），重启接着扫；reorg 先记日志，**待确认**是否回滚 SQLite 该块事件
- **配对 catalog 表** `quote_assets`（地址、symbol、decimals、`kind=eth|usdg|stock`）
- **优质项目视图**（可用 SQL 视图，不必新服务）：  
  - 创建人 ∈ 聪明钱  
  - 开盘 N 分钟内 ≥K 个 active 聪明钱买入  
  - 同类盘口里 quote 是主流股票（o1_stock）
- 配置文件：RPC、三类工厂地址、聪明钱 CSV 路径、日志级别

### 6.2 明确推迟（写在这里以免做歪）

- 自动评分用的 USD 预言机、完整闭环 PnL 引擎
- 毕业后全市场 Swap 入库
- Web 管理端（可用 sqlite3 / Datasette 凑合看）
- Long 发射台（24h 出金率高，但是 **范围外**，你若要加应升为第四类独立表）

### 6.3 「发现更多优质项目」v0 操作定义

每日（或每小时）从库里能列出：

1. 新盘：`creator_eoa` 在聪明钱集合且 `level`≥B  
2. 新盘：1 小时内 ≥2 个聪明钱买入  
3. 钱包：近 7 日 `score` 上升且有新 `launch`

输出可以是日志 `[signal]` + 表 `project_signals`（可选）。**待确认** v0 要不要第四张信号表；没有的话用查询即可。

## 7. SQLite 与 Docker

### 7.1 SQLite 约定

- 文件：`/data/robinhood_meme.sqlite3`（容器内），主机挂卷
- WAL、`busy_timeout=5000`、**单 writer**（监听进程独占写）
- 迁移：线性 SQL 文件 `migrations/001_init.sql`…，启动时执行
- 备份：停写或 `VACUUM INTO`；v0 文档说明即可
- 金额一律 **字符串或 INTEGER 最小单位**，不要用 REAL 存 wei

GORM 能开 SQLite，但四meme 是 MySQL 习惯；v0 更建议 **sqlc + 手写 schema**，类型和三张 launch 表更干净。

### 7.2 Docker（建议）

```text
服务：一个 Go 二进制
挂载：./data → /data
环境：RH_RPC_URL、RH_FROM_BLOCK、LOG_LEVEL
不在镜像里塞 RPC 密钥；用 env 或 compose env_file（勿提交）
```

公开 RPC 在调研里会 403，生产用自有节点。健康检查：进程存活 + `sync_state` 落后块数（可选读 `/health` 若加了 HTTP）。

## 8. Go 框架比对（未定，供你拍板）

对照仓库里 `go_fourmeme_v3`：go-zero + GORM + MySQL。本项目是 **链上 worker + SQLite**，不是同一形态。

| 方案 | 组成 | 适合 | 代价 | v0 建议 |
| --- | --- | --- | --- | --- |
| **A. Worker 优先** | `cobra` 或纯 `main` + `sqlc` + `modernc.org/sqlite` + `go-ethereum` | 监听、入库、日志；与需求最贴 | 以后加 API 要补路由 | **首选** |
| **B. 轻 HTTP** | A + `chi` 或 `echo` 只读查询 | 你要本地看新盘/聪明钱 | 多一个端口和鉴权问题 | 有查询需求再加 |
| **C. go-zero** | 现有熟悉度 | 想复制 fourmeme 工程习惯 | SQLite/常驻扫块不是它的主场，配置重 | 不建议 v0 |
| **D. GORM 全家** | GORM sqlite driver | 改表快 | 三套独立类型容易被合成一个 Model | 若用 GORM 也必须三个 Model 三张表 |
| **E. fx/wire + ent** | 企业注入 | 多人长期 | 对单进程过重 | 否 |

**建议拍板 A**，目录按职责拆（不要一个 `main.go` 写完）：

```text
cmd/watcher/          # 启动、配置、组装
internal/chain/       # RPC、收据、水位
internal/parser/pons|
                 o1stock|
                 o1crypto
internal/domain/      # 三个 Launch 类型、Wallet、Event
internal/store/       # SQLite，按表分文件
internal/score/       # 评分，纯函数可测
internal/logx/        # 结构化日志字段
```

HTTP、自动交易都不进 v0 目录。

## 9. 数据流与幂等

```text
RPC 块 → 分类 parser → domain 对象
                ↓
        store 事务：launch_* + launch_index
                ↓
        若地址 ∈ smart_wallets.active
                → 日志 + wallet_events
                → 更新 last_seen_at
                →（异步或定时）重算 score
```

同一 `tx_hash+log_index` 插入冲突则跳过。新盘 `token_address` 已存在：若 category 一致则忽略；不一致打 `error` 日志 **待确认** 是否覆盖。
