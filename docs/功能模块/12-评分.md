# 12 评分

- 最新更新时间：2026-09-02 14:40 (UTC+8)
- 适用范围：`internal/score`；更新 `smart_wallets` 分数列
- 来源：FR-06；底稿 §4.4
- 对应需求：FR-06
- 落地包：`internal/score`

## 职责

用 FIFO 已实现盈亏（单位 U）给钱包打分与级别。样本不足封顶。手改级别可锁。

## 边界

- 禁止按 ETH/USDG/股票分桶加总当分数
- 发盘、发盘费不是样本
- `exec_usd_per_token` 为空的卖出不是样本
- 暂停/拉黑仍可用 **尚未过期的** 历史流水评分，只是不再追加新样本
- 不建独立盈亏表；每次从 `wallet_events` 重放或增量缓存（表只留 7 天，见模块 `18`）

## 输入 / 输出

输入：某地址全部 `buy/sell` 行（有 U）。输出：`score`、`level`（未锁定时覆盖）、`score_win_rate`、`score_profit_usd`、`score_sample_n`。

写入口与扫块同一 SQLite writer。

## 样本定义

一笔样本 = 一笔 `sell` 且 FIFO 产生了匹配（匹配数量>0）。`score_profit_usd` = 这些样本已实现盈亏之和（USD）。

`sample_n < 8`：算出的分数与 49 取小（进不了 A/S）。

## 公式（必须按此实现，可单测）

```text
胜率     = 已实现盈亏>0 的卖出笔数 / 有匹配的卖出笔数
盈利归一 = tanh(累计已实现盈亏U / 10000)
规模归一 = tanh(有匹配的卖出笔数 / 40)
新鲜归一 = 近 14 天有匹配卖出的笔数 / 卖出笔数

分数 = 100 × (0.40×胜率 + 0.35×max(盈利归一,0) + 0.15×规模归一 + 0.10×新鲜归一)
       − 20 × max(−盈利归一, 0)
截断到 [0, 100]
```

分母为 0：不打分，保持空或 0 分且 sample_n=0，不要除零。新鲜分母为有匹配的卖出笔数；近 14 天按 `chain_time` UTC。**表只留 7 天时，14 天窗口与保留期取小（最多 7 天样本），禁止读已删行。** 无卖出则新鲜=0。

| 级别 | 分数 |
| --- | --- |
| S | ≥ 80 |
| A | ≥ 65 |
| B | ≥ 50 |
| C | ≥ 35 |
| D | < 35 |

`level_locked=1`：重算仍更新 `score` 与快照列，**不改** `level`。

## 主路径

1. 触发：默认每小时，或新插入卖出累计每 100 笔（先到先执行）。配置 `RH_SCORE_INTERVAL_SEC` 默认 `3600`。
2. 对 `smart_wallets` 全表地址（含 paused/blacklisted）重算。有界：单次循环可分批，避免锁表过久。
3. 纯函数 `ComputeScore(samples) -> Result`。
4. UPDATE 分数列；`updated_at=UTC`。
5. 日志可用 info：钱包、分数、样本数、累计盈亏U；键名中文。不必每钱包都打，可只打分数变化超过 1 分的。

## 落库

只更新名单上的评分字段，不写 `wallet_events`。

## 失败

某钱包 decimals 混乱导致 FIFO 失败：该钱包打 `[错误]`，跳过本次分数更新，不要写 0 分冒充算完。

## 依赖

fifo、store。禁止 HTTP 同步重算全表（只读查询可读已存分数）。

## 验收

- 构造 8 笔以下盈利样本：score≤49，级别进不了 A。
- 公式用固定样本对 tanh 手算对照。
- 锁定级别后分数变、级别不变。

## 调研

无。ETH 缺价或股票盘未落地会导致样本变少，不得填 0 U 凑样本。过期流水删除后样本只剩 7 天窗。
