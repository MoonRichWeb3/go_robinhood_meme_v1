# 02 合约目录与分流

- 最新更新时间：2026-09-02 14:40 (UTC+8)
- 适用范围：`internal/contracts`、`internal/venue/route`
- 来源：`docs/架构/02`；`docs/调研/02`（地址与 topic0 的唯一事实源）
- 对应需求：FR-01
- 落地包：`internal/contracts`、`internal/venue/route.go`

## 职责

启动加载合约目录；对每条 log 用 `address + topic0` 找到唯一处理入口；维护运行时 **池登记** 与 Pons **曲线登记**。地址变更只改目录，不改 `if` 魔法数。

## 边界

- 不解码 ABI（交给各 venue）
- 不写 SQLite
- 不把 Debot 名、代币 symbol 当分类
- `role=ignore` 的 log 直接丢弃，不当 Long

## 输入 / 输出

| | 内容 |
| --- | --- |
| 输入 | 规范化后的 log（address 小写、topic0）；同笔 tx 的 receipts 上下文由 app 传入 Decode |
| 输出 | `RouteHit`：`venue` + `kind`（create / curve_buy / curve_sell / graduated / v4_swap / v4_init / ignore / unknown） |
| 副作用 | 内存：`pool_id → {token, category}`；`curve → token`（由创建/毕业路径登记，本包提供接口） |

v0 **不登记** Bags / hood.fun / pools.trade 工厂。扫到未登记地址 → 忽略。

## 分流顺序（一块内，对每条 log）

与架构图 11 一致，实现必须按这次序，禁止「先猜盘口再看地址」：

1. `role=ignore` 且地址命中 → 丢弃。
2. 目录命中 `address+topic0` → 按 venue/kind 分发。
3. topic0 是 Pons `CurveBuy`/`CurveSell`/`PoolGraduated`/`LaunchSwept` → Pons 适配器（先查曲线登记）。
4. PoolManager `Swap` → `v4fill`：用 poolId 查池登记；未命中丢弃。
5. PoolManager `Initialize` → 仅当本块已有四类创建需要补 `pool_id`，或创建交易同笔已能关联；无关池丢弃。
6. 其它 → 忽略。不要尝试按代币名猜。

同一条 log 只走一个 handler。

## 池登记 / 曲线登记

| 登记 | 键 | 值 | 何时写入 | 重建 |
| --- | --- | --- | --- | --- |
| 池 | `pool_id` 小写 `0x`+64 hex | token + category | o1/Long 创建；Pons 毕业；同笔 Initialize | 启动从四张 `launch_*` 已有 `pool_id` 加载 |
| 曲线 | `curve_address` 小写 | token | Pons `TokenLaunched` | 启动从 `launch_pons.curve_address` 加载 |

进程重启必须重建，否则 Swap 全部丢失。丢失时打 `[错误]` 类型=池登记缺失。

## 日志

- 启动目录条数、必填校验失败 → `[错误]` 并退出。
- 已知 topic 无 handler（编程错误）→ `[错误]`。

## 失败

目录命中但 Decode 失败：见各新盘模块。route 本身对未登记 log **静默忽略**（不是错误）。

## 依赖

contracts 不依赖 store。app 在启动后调用 store 重建登记。venue 只通过 route 被调用。

## 验收

- 缺 Pons 或 o1 加密工厂条目进程起不来。股票工厂、LongLauncher 本期缺了仍能起（ignore）。
- Airlock 上 Create 不产生 `launch_long`。
- 未入库 pool 的 Swap 不写交易表、不刷价。
- 股票工厂 `Launched` 本期不入库。
