# 01 扫块与水位

- 最新更新时间：2026-09-02 16:25 (UTC+8)
- 适用范围：`internal/chain`、`internal/app` 的块循环；不含盘口 ABI
- 来源：`docs/需求/01` FR-10；`docs/架构/01` §2/§4/§10；`docs/架构/03` 图 5、图 13；`docs/调研/01`、`04`
- 对应需求：FR-10；验收 AC-07
- 落地包：`internal/chain`、`internal/app`

## 职责

持续追上 Robinhood Chain（chainId `4663`）最新块，把 **整块收据**交给编排层；维护 `sync_state` 水位；检测到块哈希分叉时只更新水位并打日志。

## 边界

- 不解析 topic、不写 `launch_*` / `wallet_events`
- 不发交易、不订阅公网 WebSocket 当主路径（WS 可作为后续加速，本模块 v0 以 HTTP 轮询为准）
- 不在本层做 `if pons`
- 重组不删已记账行（过期 7 天删除是模块 `18` 的保留任务，不是重组回滚）

## 输入 / 输出

| | 内容 |
| --- | --- |
| 输入 | `RH_RPC_URL`、`RH_FROM_BLOCK`、`RH_POLL_MS`、`RH_MAX_BLOCKS_PER_TICK`、上次水位 `(last_block, last_hash)` |
| 输出 | `BlockBatch`：块号、块哈希、父哈希、块时间（UTC）、本块全部 receipts（含 logs、`tx_index`） |
| 副作用 | 读链；**不写业务表**。水位 UPDATE 由 app 在本块 commit 后调用 store |

## 主路径

1. 启动：读 `sync_state`（`name=rh_4663`）。无行则从 `RH_FROM_BLOCK` 起，插入水位（`last_hash` 空直到扫完第一块）。
2. `eth_blockNumber` 得头。若头 ≤ 已处理，睡眠 `RH_POLL_MS` 再询。
3. 一次最多拉 `RH_MAX_BLOCKS_PER_TICK` 块（默认 `10`）。单轮对 `[next,end]` 做有界并发预取，并发固定为 `min(8, RH_MAX_BLOCKS_PER_TICK)`，预取结果最多保留本轮块数；不新增配置。RPC 可以乱序完成，但后续重组检查、`ProcessBlock` 和原子水位提交严格按块号升序。遇到首个按序错误立即取消本轮尚未完成的请求，不处理、更不提交后块。禁止一次无界追到头。
4. 对每个块号 `n`：
   1. `eth_getBlockByNumber(n, true)` 取完整交易及 hash、parentHash、timestamp。
   2. 若 `n == last_block+1` 且 `parentHash ≠ last_hash`（且 last_hash 非空）：视为重组。打 `[错误]`（类型=重组），**只改水位 hash/块号到当前 canonical 的 n-1 或本块**（实现：把 `last_hash` 更新为当前链上该高度的父块事实后继续扫本块），**不删除任何已写入行**。
   3. 拉收据：启动后对目标 RPC **探测一次** `eth_getBlockReceipts`。支持则本进程全程用，并让块详情与整块收据两个 RPC 并发执行，任一失败取消另一侧；不支持或探测出错则 **固定** 回退「块详情 + 逐笔 `eth_getTransactionReceipt`」（并发 ≤8），打一次 `[错误]` 类型=RPC回退。不要每块重新探测、不要来回切换。
   4. 规范化：每笔 receipt 带 `tx_index`（块内下标，从 0）；每条 log 带协议 `log_index`（收据内下标）。
   5. 交给 app：`ProcessBlock(batch)`。
   6. **仅当** `ProcessBlock` 返回成功：UPDATE `sync_state`：`last_block=n`，`last_hash=本块 hash`。
5. RPC 失败（含 429/5xx）：打 `[错误]`，**不推进水位**，由轮询外层统一指数退避（建议 200ms→上限 5s），下一轮从同一 `n` 重试。预取层和收据层不做内部重试，禁止重试放大或跳块。

## 配置默认值

| 项 | 默认 | 理由 |
| --- | --- | --- |
| `RH_POLL_MS` | `80` | 块约 100ms；3s 一轮询不可接受 |
| `RH_MAX_BLOCKS_PER_TICK` | `10` | 落后时可追赶，又不一次打爆内存 |
| `RH_HTTP_UA` | 非空固定产品名+版本 | 公开 RPC 无 UA 会 403（调研 `01`） |
| `RH_RPC_TIMEOUT_MS` | `8000` | 单次调用上限 |
| chainId 校验 | 启动 `eth_chainId` 必须为 `4663` | 连错链直接拒绝启动 |

生产用自有/供应商节点。公开 RPC 仅开发：必须带 UA，遇到 429 退避，不得空转狂打。

## 落库

`sync_state` 一行：

| 列 | 值 |
| --- | --- |
| `name` | `rh_4663`（PK） |
| `last_block` | 已成功处理的最高块 |
| `last_hash` | 该块哈希，小写 `0x` |
| `updated_at` | UTC |

禁止自增 id。重组不另建表。

## 日志

| 何时 | 标签 | 必填键 |
| --- | --- | --- |
| 落后超过 50 块 | `[错误]` | 类型=落后 已处理块= 链头= |
| 重组 | `[错误]` | 类型=重组 块高= 旧哈希= 新父哈希= |
| 收据方法回退 | `[错误]` | 类型=RPC回退 方法= |
| 正常追赶不必每块打 info | — | 可用 debug；面向人的默认级别不要刷屏 |

## 失败

| 情况 | 水位 | 写库 |
| --- | --- | --- |
| RPC 超时/5xx/429 | 不动 | 不写业务 |
| 某块 receipts 为空但块存在 | 仍处理（空块合法） | 只更新水位 |
| `ProcessBlock` 返回失败（例如写库 busy 超限） | 不动，重试同块 | 业务由 store 事务决定；禁止半块提交后前进 |
| 解析失败（venue） | **仍前进** | 该 log 跳过，见模块 `02`/`03` |

半块：一块内多条事件必须同一写事务。失败则整块重做（主键幂等）。

## 依赖

只依赖：config、RPC 客户端、store 的 `sync_state` 读写。禁止依赖 venue。

## 验收

- 重启后从 `last_block+1` 续扫，已入库行仍在（AC-07）。
- 人为制造 parent 不匹配：有重组日志，历史 `wallet_events` **未过期**行数不因重组减少。
- 人为让同轮 RPC 乱序完成：`ProcessBlock` 仍严格升序；中间块读取或提交失败时后块不处理，未完成请求收到 context 取消；预取并发不超过 8。
- 轮询间隔配置为 3s 时健康检查应能看出落后（不要把 3s 当默认）。
