# 18 交易表保留与分批删除

- 最新更新时间：2026-09-02 14:40 (UTC+8)
- 适用范围：仅 `wallet_events` 过期清理；`internal/store` + `internal/app` 小时任务
- 来源：用户 2026-09-02 口径（交易表只留 7 天，每小时删，禁止一次删太多卡住）；需求 FR-10 持久化仍适用于 **未过期** 行
- 对应需求：FR-10 补充；与 FR-02「拉黑不删流水」不冲突（拉黑不主动删；过期由本任务删）
- 落地包：`internal/store` 的有界 DELETE；app 定时切面走 **同一写队列**

## 职责

`wallet_events` 只保留链上时间 **近 7 个自然日（UTC）** 的行。每小时跑一轮清理。每轮拆成多批 DELETE，批次之间让出写锁，避免一次扫光全表卡住扫块。

## 边界

- **只删** `wallet_events`。不删 `launch_*`、`launch_index`、`smart_wallets`、`quote_assets`、`sync_state`
- 不在 HTTP 上提供删接口
- 不在扫块事务里顺带无界 DELETE
- 不做每小时 `VACUUM`（会长时间锁库）
- 过期删除后 FIFO/评分只看见剩余行，这是产品接受的结果，不要为保留仓位而豁免过期买

## 输入 / 输出

| 项 | 值 |
| --- | --- |
| 保留窗 | `chain_time < now_utc - 7 days` 的行视为过期。`now` 用处理时间 UTC |
| 周期 | 每 3600s（`RH_EVENT_PURGE_INTERVAL_SEC`，默认 3600） |
| 每批条数 | `RH_EVENT_PURGE_BATCH` 默认 **500** |
| 批间隔 | `RH_EVENT_PURGE_SLEEP_MS` 默认 **100** |
| 单轮上限 | `RH_EVENT_PURGE_MAX_PER_RUN` 默认 **5000**（约 10 批）；超出则本轮停，下一小时继续。禁止一轮删光百万行 |

输出：本轮删除条数；写中文日志。无过期行则静默或 debug。

## 主路径

1. 定时器触发（与扫块同进程，**入队 writer**，不要第二写连接）。
2. 截止时刻 `cutoff = now_utc - retention`。比较列用 `chain_time`（链上时间），不用 `ingested_at`（补扫迟到不应让旧成交多活几天）。
3. 循环直到本轮达到 `MAX_PER_RUN` 或本批 0 行：

```sql
DELETE FROM wallet_events
WHERE id IN (
  SELECT id FROM wallet_events
  WHERE chain_time < :cutoff
  ORDER BY chain_time ASC, id ASC
  LIMIT :batch
);
```

4. 每批结束后 `sleep(PURGE_SLEEP_MS)`，让扫块/刷价插队。
5. 一批失败（busy）：打 `[错误]`，中止本轮，水位与扫块不受影响。下一小时重试。不要在失败时加大 LIMIT。
6. 成功：打一行摘要（删除条数、截止时间、是否因单轮上限提前停）。

SQLite 若未编译 `UPDATE/DELETE LIMIT`，必须用上面的 `id IN (SELECT … LIMIT)`，禁止 `DELETE FROM wallet_events WHERE chain_time < ?` 无 LIMIT。

## 与 FIFO / 评分

- 卖出匹配只使用 **表里还在** 的买入。过期买被删后，后到的卖可能超仓，按模块 `09` 打 `[错误]` 类型=卖出超仓，不得用 0 成本。
- 评分只扫描剩余行；`fresh_norm` 的 14 天窗口与 7 天保留取交集（最多 7 天样本）。见模块 `12`。
- 名单拉黑仍不额外删行；行只因过期消失。

## 索引

模块 `09` 已有 `(wallet_address, chain_time)` 等。过期扫描依赖 `chain_time`：迁移增加 `INDEX idx_wallet_events_chain_time ON wallet_events(chain_time)`（若 001 没有则 `002`）。

## 日志

```text
[清理] 时间=… 类型=清理 表=交易 截止=… 本轮删除=1234 提前停止=否
```

失败：`[错误] 类型=清理失败`。禁止每批打 info 刷屏。

## 失败

| 情况 | 行为 |
| --- | --- |
| writer 排队过久 | 本轮跳过，`[错误]`，扫块优先 |
| cutoff 解析失败 | 不删 |
| 误配保留天数 0 | 启动拒绝（见模块 17） |

## 依赖

只 store + clock。禁止 RPC、禁止币安 HTTP。

## 验收

- 插入 `chain_time` 为 8 天前的行，跑一轮（可单测假时钟）后该行消失；7 天内的行仍在。
- 过期 20000 行：单轮最多删 `MAX_PER_RUN`，扫块在批间隔仍能拿到写锁（实现用「批次间 sleep + 同队列」保证，测试可用短 sleep）。
- 重启不丢 **未过期** 交易与新盘（AC-07 收窄为保留窗内）。
