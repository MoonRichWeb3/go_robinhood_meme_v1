## 1. 背景与目标

运营需要在 Robinhood Chain 上尽早发现四类 meme 新盘，盯住一批评分可解释的聪明钱包，用真实成交算盈亏，从流水里筛优质项目。

v0 **只发现、只记账，不下单。**

| 目标 | 成功时能做到 |
| --- | --- |
| G1 新盘可见 | 四类范围内，工厂创建发生后能查到：分类、配对、创建人、创建时间 |
| G2 聪明钱可运营 | 名单可随时增删改（含暂停/拉黑），运行中生效，不必重启 |
| G3 行为可追溯 | 聪明钱发盘/买/卖在中文日志和交易记录里能对上：谁、哪个币、方向、数量、成交单价 U、交易哈希 |
| G4 真实盈亏 | 用成交单价和数量按 FIFO 算出已实现盈亏。例：买 100 份×1U，卖 50 份×2U → 盈亏 50U |
| G5 币对可读 | 已监控且发生过成交的项目，列表能看到单价 U（给人看，不必逐笔改表） |
| G6 筛优质盘 | 能列出：聪明钱发的盘、短时间内多名聪明钱同买、胜率高的钱包所发之盘 |

## 2. 范围

### 2.1 做（v0）

- 监控四类盘口的 **全市场新盘** 并入库
- 维护聪明钱包名单；仅对 **当前有效** 名单记录发盘/买卖
- 交易记录保存实际成交数量与单价 U，用于 FIFO 盈亏与评分
- 币对列表展示单价 U（有成交才更新，允许短暂延迟）
- 中文结构化日志
- 本机只读查询（新盘、某钱包流水、健康状态）
- 数据本地持久化；重启不丢；同一链上事件不重复记账
- 时间一律 UTC

### 2.2 不做（v0）

- 自动买卖、跟单、热钱包、私钥
- Bags、hood.fun、pools.trade、Bankr（Long 已纳入，其它仍除外）
- 以 Debot / GMGN 网页为链上事实来源（可作钱包出处标签）
- 规定钱包名单从哪里导入（CSV/API 不在需求内；以库里的名单为准）
- 多链、回测界面、公网鉴权产品、Web 管理后台
- 链重组后回滚已写入记录
- 全市场买卖写入交易表（价格刷新可用全市场成交，交易表仍只记聪明钱）
- 未实现盈亏、独立盈亏表、预计算信号表 `project_signals`
- 存原始 JSON / 原始回执

### 2.3 已拍板约束（实现选型不得推翻）

| 项 | 决定 |
| --- | --- |
| 语言与服务形态 | Go；常驻监听 + 最小只读 HTTP；框架用 go-zero |
| 存储 | 本地 SQLite，可随容器挂卷 |
| 交易表主键 | 区块号（8 位左补零）+ 交易下标（4 位）+ 日志下标（4 位）拼接；缺日志下标为 0 |
| 钱包表主键 | 地址小写 |
| 其它表主键 | 业务自然键（如代币地址），禁止无意义自增 id |
| 查询大小写 | 地址/哈希写入小写；查询大小写都能命中；无 `0x` 不算同一地址 |

## 3. 术语

| 词 | 含义 |
| --- | --- |
| 四类盘口 | Pons V2；o1 股票配对；o1 加密货币配对；Long |
| 新盘 | 上述四类工厂/入口上的创建事件所产生的 meme 代币 |
| 聪明钱包 / 名单 | 运营维护的地址集合；只有 `有效` 状态才触发盯盘 |
| 用户地址 | 实际拿到或交出 meme 的钱包，不是路由合约 |
| 成交单价 U | 本笔用户实际付出/收回折成的 **1 枚 meme 多少美元** |
| 展示单价 U | 列表上给人看的 1 枚 meme 多少美元，取该币 **最近一笔已监控成交** |
| 已实现盈亏 | FIFO 匹配后：匹配数量 ×（卖出价 U − 对应买入价 U） |
| 有效名单 | 库中存在、且状态为有效（非暂停、非拉黑）的地址 |

## 4. 使用场景

1. **发现新盘**：四类工厂出现创建 → 入库 → 打 `[新盘]` 日志 → 列表能查到。
2. **改名单**：运行中增加有效地址 → 之后的链上行为开始盯；删除或拉黑 → 立刻不再记新流水（历史保留）。
3. **盯买卖**：有效名单地址买入/卖出四类已入库盘口 → 中文日志 + 交易记录（数量、成交单价 U）。
4. **看盈亏**：同一钱包对同一代币，买 100×1U 再卖 50×2U → 已实现 50U。
5. **看币价**：某已入库币有成交 → 数秒内列表单价 U 更新；从未成交则单价为空。
6. **筛项目**：查出聪明钱所发、或开盘后多名聪明钱买入的盘。

## 5. 功能需求

### FR-01 新盘入库

- 四类盘口的创建 **全部入库**，与聪明钱名单无关。
- 分类 **只由创建交易打到的工厂/入口决定**，不用 Debot 标签、不用代币名猜测。
- Long **只认 Long 入口**，不得把其它共用底层的创建算成 Long。
- 四类协议字段不同，必须 **分类型保存**，禁止一张万能新盘表吞掉曲线地址、股票报价、Hook、毕业状态等。
- 列表需要一张瘦目录：分类、名称、配对、创建人、创建时间、展示单价 U。协议细节在对应类型记录里。
- 必答信息：分类、配对名称、创建人（签名发起的 EOA；事件里的 creator/deployer 若不同也要能区分）、创建时间（UTC）、创建交易。
- 同一代币已存在：分类相同则忽略；分类冲突则报错，不覆盖。
- Pons 毕业要记下阶段变化；毕业本身不是交易记录。

配对名称：Pons 为 ETH / USDG / 其它已识别报价；o1 股票为股票代码；o1 加密为 ETH 或 USDG；Long 为报价资产代码。识别不出则标记未知，不得瞎填。

### FR-02 聪明钱包

- 一条地址一行。可以是普通钱包，也可以是运营放入的 Deployer 合约。
- 不得把协议合约（工厂、路由、池管理、Long 入口、底层 Airlock 等）默认当作聪明钱。
- 状态：有效 / 暂停 / 拉黑。只有 **有效** 触发 FR-03。
- 可记录：名称、来源、主类型（发盘/常胜/开盘枪/跟风/KOL/未分类）、标签、级别、分数、备注。
- 主类型单选；兼具多种行为用标签补充。
- 名单 **以库为准**。运行中增删改必须在 **1 秒内**被监听用上，禁止只在启动读一次。
- 新加或恢复为有效：只盯 **生效之后** 的链上行为，不回补已经处理过的历史块。
- 删除 / 暂停 / 拉黑：停止新日志与新交易记录； **不删** 历史流水。
- 改名称：之后日志用新名；不改历史行。

### FR-03 聪明钱发盘与买卖

仅当地址属于 **当前有效名单** 时记录。

| 行为 | 记谁 | 方向 |
| --- | --- | --- |
| 四类创建 | 交易发起人，以及名单中的 Deployer/creator 合约 | 发盘 |
| 买入/卖出 | 实际拿到或交出 meme 的地址 | 买 / 卖 |

- 经 GMGN 等聚合器多跳 **要记**，仍按代币转账归因，并标明入口类型（能识别则记名字，否则未知）。
- 路由、发射辅助合约、池管理、协议入口 **不得**当成用户，除非被显式写入名单（不建议）。
- 全市场成交 **不写** 交易表；只写聪明钱。
- 同一链上日志只记一行；重复则跳过。
- 发盘可记 0 金额或发射费；发盘不进入 FIFO。

### FR-04 成交价与已实现盈亏

- 交易记录必须有：数量、本笔 **实际成交单价 U**（喂价暂不可得则 U 为空，不得写成 0）。
- 盈亏 **只用** 交易记录里的数量和成交单价 U，不用币对列表上的延迟展示价。
- 按 **同一钱包 + 同一代币**、链上时间顺序 FIFO：

```text
买：形成仓位（数量, 成交单价U）
卖：从最早未消耗仓位扣减

已实现盈亏U = Σ 匹配数量 × (卖出成交单价U − 该仓买入成交单价U)
```

例：买 100 份单价 1U，卖 50 份单价 2U → **50U**；剩 50 份成本仍为 1U。

- 一笔卖匹配多笔买：各段盈亏相加。
- 卖出超过持仓：能匹配的部分照算；超出部分报错，不得用 0 成本制造盈利。
- 成交单价 U 为空的行不参与匹配、不参与评分。
- v0 不算未实现盈亏，不另建盈亏表。

### FR-05 币对展示单价

- 展示在新盘目录上，单位 **U**，方便人读。
- **仅** 已入库、且监控到 **有成交** 的资产才更新；从未成交则单价为空。不得用创建时的中间价冒充成交价。
- 成交来源可以是该盘口全市场成交（不限聪明钱），用于刷新展示价；仍不把这些成交写入交易表。
- 更新 **不必逐笔写库**，允许批量，默认间隔 **3 秒**；无新成交不写。窗口内多笔取最后一笔成交单价 U。
- 协议明细记录 **不存价格**。
- 喂价缺失时本次不刷 U（保留上次或空），禁止写 0。

### FR-06 评分（折 U）

- 用 FR-04 的已实现盈亏，禁止按 ETH/USDG/股票分桶当总分。
- 样本不足 8 笔：分数封顶 49（进不了 A/S）。
- 一笔样本 = 一笔卖出按 FIFO 匹配后的结果。发盘与发盘费不算。
- 公式：

```text
胜率     = 已实现盈亏>0 的卖出笔数 / 有匹配的卖出笔数
盈利归一 = tanh(累计已实现盈亏U / 10000)
规模归一 = tanh(有匹配的卖出笔数 / 40)
新鲜归一 = 近 14 天有匹配卖出的笔数 / 卖出笔数

分数 = 100 × (0.40×胜率 + 0.35×max(盈利归一,0) + 0.15×规模归一 + 0.10×新鲜归一)
       − 20 × max(−盈利归一, 0)
截断到 [0, 100]
```

| 级别 | 分数 |
| --- | --- |
| S | ≥ 80 |
| A | ≥ 65 |
| B | ≥ 50 |
| C | ≥ 35 |
| D | < 35 |

- 未锁定级别时，重算覆盖级别。可手改级别并锁定。
- 暂停/拉黑后仍可用历史流水评分，只是不再追加新样本。

### FR-07 优质项目查询

v0 用查询现算， **不预写信号表**。至少能回答：

1. 创建人（EOA 或名单中的 creator 合约）是聪明钱，且级别 ≥ B
2. 开盘后 1 小时内 ≥ 2 个有效聪明钱买入
3. 近 7 日分数上升且有新发盘的钱包

命中可打 `[信号]` 日志，并可用只读查询列出。

### FR-08 只读查询

- 提供最小本机/内网只读接口：健康检查、新盘列表、某钱包流水。
- 不是下单接口，默认不面向公网、不作为管理后台。

### FR-09 日志

- 给人看的标准输出必须是 **中文** 键名与中文类型，结构化 `键=值`。
- 库内枚举可用英文；日志禁止英文键如 `kind=`、`spot_quote=`。

| 标签 | 何时 |
| --- | --- |
| `[新盘]` | 四类创建入库 |
| `[聪明钱-发盘]` / `[聪明钱-买入]` / `[聪明钱-卖出]` | 有效名单命中 |
| `[价格]` | 展示单价刷入目录时（每个被刷新的币一行，不要每笔全市场成交打一次） |
| `[错误]` | 解析失败、缺价、分类冲突、卖出超仓等；禁止静默丢弃 |
| `[信号]` | FR-07 命中 |

买卖日志必须带数量与成交单价 U；能算出 FIFO 时卖出带已实现盈亏 U。时间为 UTC（处理时间与链上时间都要能看出来）。

盘口展示名：`Pons` / `o1股票` / `o1加密` / `Long`。

### FR-10 运行与数据完整性

- 重启后已入库新盘、交易、名单、展示价不丢。
- 同一交易事件不重复入库。
- 检测到块哈希分叉：记下水位变化并打日志， **不删除、不回滚** 已写入记录（允许残留分叉上的行）。
- 解析失败必须打错误日志。
- 不存原始 blob / `raw_json`；解不出的字段丢弃，以后需要再加业务字段。

## 6. 数据需求（实体，不是表设计）

后续设计再落 DDL。此处只约束 **必须有的业务对象与规则**。

| 对象 | 作用 | 主键含义 |
| --- | --- | --- |
| 聪明钱包 | 名单与评分 | 地址（小写） |
| 新盘目录 | 列表与展示单价 U | 代币地址 |
| 四类新盘明细 | 各协议特有信息 | 代币地址；与目录一一对应 |
| 聪明钱交易 | 发盘/买/卖流水 | 区块号+交易下标+日志下标拼接 |
| 报价资产 | ETH/USDG/股票等元数据 | 资产地址 |
| 同步水位 | 扫到哪、是否分叉 | 链标识（一条链一行） |

字段级要求（验收用，细节到设计阶段展开）：

- 地址、交易哈希写入小写，查询大小写不敏感；缺 `0x` 不视为同一地址。
- 交易记录含：链坐标、钱包、方向、分类、代币、数量、报价资产、成交单价（报价单位与 U）、入口类型。
- 新盘目录含：分类、名称、配对、创建人（EOA 与合约侧 creator）、创建时间、展示单价 U 及对应成交坐标。
- 明细含该类型跟盘所需协议身份（如曲线、池、报价资产、毕业阶段）， **不含** 价格列、不含原始 JSON。
- 金额用精确值（最小单位整数或十进制字符串），不用浮点存链上最小单位。
- 时间 UTC。

## 7. 折 U 规则

链上先得到本笔成交（报价资产数量 / meme 数量），再乘「1 单位报价资产多少美元」得到成交单价 U。

| 报价 | v0 规则 | 缺口 |
| --- | --- | --- |
| USDG | 先按 1 美元 | 脱锚策略未定 |
| ETH | 乘 ETH 美元价 | **喂价未定**，未就绪不得假装有价 |
| 股票代币 | 乘该股美元价 | **喂价未定** |
| 未知 | 事件仍可记，U 为空 | 不进评分、不刷展示 U |

没有可靠喂价时：交易记录 U 为空、不参与评分；目录本次不刷展示 U。 **任何美元列禁止用 0 冒充。**

成交数量如何从四类协议事件算出，以 `docs/调研/` 为准，在「设计」阶段引用，不在本需求重写公式。

## 9. 验收

| 编号 | 给定 | 则 |
| --- | --- | --- |
| AC-01 | 四类各出现一笔真实创建 | 目录与对应类型记录都有；分类正确；能回答配对与创建人 |
| AC-02 | 把某地址加入有效名单后，该地址发生买入 | 出现中文买入日志与一条交易记录，含数量与成交单价 U |
| AC-03 | 将该地址拉黑或删除后再买入 | 不再出现聪明钱日志与新交易记录；旧记录仍在 |
| AC-04 | 买 100×1U 再卖 50×2U | 已实现盈亏为 50U |
| AC-05 | 已入库币发生成交（哪怕不是聪明钱） | 约 3 秒内目录单价 U 变为最近成交；无成交的币单价仍空 |
| AC-06 | 同一事件处理两次 | 交易记录仍一条 |
| AC-07 | 进程重启 | 新盘、交易、名单、上次展示 U 仍在 |
| AC-08 | 只读查询 | 能列出新盘、某钱包流水、健康状态 |
| AC-09 | 解析失败或无法折 U | `[错误]` 日志；美元列不为 0 |
| AC-10 | 查询地址大小写混用 | 能命中同一钱包/代币 |

示例日志形态（键名必须中文，数值为示意）：

```text
[新盘] 时间=… 盘口=Long 代币=0x… 配对=AMZN 创建人=0x… 名称=SENDER
[聪明钱-买入] 时间=… 钱包=0x… 方向=买入 数量=100 成交单价U=1 交易=0x…
[聪明钱-卖出] 时间=… 钱包=0x… 方向=卖出 数量=50 成交单价U=2 已实现盈亏U=50 交易=0x…
[价格] 时间=… 盘口=Long 代币=0x… 单价U=2 来源=最近成交
```
