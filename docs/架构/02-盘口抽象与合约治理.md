# 02 盘口抽象与合约治理（v0）

- 最新更新时间：2026-09-01 21:45 (UTC+8)
- 适用范围：四类 meme 盘口如何分层实现、链上多合约如何登记与分流
- 来源：需求 FR-01～FR-03；调研 `02`/`04`/`06`/`07`/`09`
- 合约地址与 topic 以 `docs/调研/02` 及对应盘口文档为准，本文只定 **治理方式**
- 图：[`03-架构图.md`](03-架构图.md) 图 11、图 12

## 结论先行

**按盘口拆适配器，按角色登记合约，按日志地址+topic0 分流**（图 11、图 12）。不要一个 `switch` 解析四种 ABI。不要用「万能 Launch」结构体。共享的只有：块循环、v4 Swap 二次分发、Transfer 归因、折 U、FIFO、存储。

分类 **只认创建交易打到的工厂/入口**。Long 只认 LongLauncher，不认裸 Airlock。

---

## 1. 为什么必须拆四类

四类在链上不是同一套字段（需求 FR-01）：

| | Pons | o1 股票 | o1 加密 | Long |
| --- | --- | --- | --- | --- |
| 创建入口 | Factory / LaunchAndBuy | 股票工厂 | 加密工厂 | LongLauncher |
| 内盘 | 每币一条曲线 | 无（创建即 v4） | 同左 | 同左 |
| 报价 | ETH 或 USDG | 股票代币 | ETH 或 USDG | 股票 numeraire（已核样本） |
| 买卖日志 | 曲线 CurveBuy/Sell；毕业后 v4 Swap | PoolManager.Swap | 同左 | 同左 |
| 身份键 | `curve` → 毕业后才有 `pool_id` | 创建即 `pool_id` | 同左 | 同左 |
| Hook | 毕业后 Pons meme hook | 股票 LaunchHook | **另一套** LaunchHook | DopplerHookInitializer（跨产品单例） |

混成一张宽表会出现：Pons 开盘 `pool_id` 空、股票盘 `curve` 空、o1 两个 Hook 填错仍能编译。故 **四个 domain 类型 + 四张明细表 + 一张瘦目录**。

o1 股票与 o1 加密字段相近也 **分适配器、分表、分 Hook 常量**，禁止复用同一个 stock 结构体去接加密工厂。

## 2. 抽象层级（由稳到变）

```text
共享（与盘口无关）
  块循环、收据、水位
  地址规范化、交易主键拼接
  有效名单、FIFO、评分、中文日志
  折 U（喂价端口）
  v4 Swap 的「poolId → 已入库代币」二次分发
  Transfer 最后一跳 EOA（用户地址）

盘口适配器（一种盘口一个包）
  认自己的创建事件
  解自己的领域对象
  认自己的内盘成交（仅 Pons 曲线）
  毕业/阶段（仅 Pons）

合约目录（配置）
  每个地址：角色、所属盘口、关注的 topic0
```

**允许的接口（小而稳）**：

```text
Venue
  Name() Category          # pons / o1_stock / o1_crypto / long
  MatchCreate(log) bool
  DecodeCreate(tx, logs) (Launch, error)

Pons 另加
  MatchCurveTrade / DecodeCurveTrade
  MatchGraduated / DecodeGraduated
```

**不要**做成一个巨大 `Venue`：强迫 Long 实现 `DecodeCurveTrade`、强迫 Pons 在创建时填 `pool_id`。没有的行为就没有方法。

创建结果写入目录时，各适配器实现同一个窄接口即可：

```text
LaunchIndexView
  Token / Category / Pair / CreatorEOA / CreatorContract / CreatedAt / Tx
```

明细类型互不嵌入：`PonsLaunch`、`O1StockLaunch`、`O1CryptoLaunch`、`LongLaunch`。

## 3. 合约目录：如何管理多个合约

链上地址很多：四套工厂、LaunchAndBuy、两条 o1 Hook、LongLauncher、Airlock、PoolManager、Universal Router、GMGN 代理、USDG、WETH…… **禁止在业务 `if` 里散落魔法地址。**

### 3.1 目录是唯一对照表

配置（或 `internal/contracts` 生成表）每条记录：

| 字段 | 用途 |
| --- | --- |
| `address` | 小写 `0x` |
| `role` | `factory` / `launch_and_buy` / `hook` / `pool_manager` / `router` / `aggregator` / `quote` / `ignore` |
| `venue` | `pons` / `o1_stock` / `o1_crypto` / `long` / `shared` / `none` |
| `topics` | 本地址要匹配的 topic0 列表 |
| `note` | 人类说明 |

`role=ignore`：Airlock 裸 `Create`、Bankr 等 v0 不听。扫到只跳过，不当 Long。

`role=pool_manager` 且 `venue=shared`：所有 v4 Swap/Initialize 先入共享通道，再按 **已登记 poolId** 分给盘口。

启动时校验：需求里的四类入口地址必须在目录中且 `venue` 正确。缺条目则拒绝启动。

地址变更只改目录，不改分流代码。调研更新合约时，先改 `docs/调研/02`，再改目录。

### 3.2 分流顺序（一块内）

见图 11。

```text
对每条 log：
  1. 查目录：address + topic0 是否登记
  2. 未登记 → 忽略（不要尝试按代币名猜盘口）
  3. venue=pons|o1_*|long 且是创建 topic → 对应 Venue.DecodeCreate
  4. venue=pons 且是曲线买卖/毕业 → Pons 适配器
  5. venue=shared 且是 PoolManager.Swap
        → 用 poolId 查「池登记」
        → 命中已入库盘口：当作该盘 Fill（可刷价；聪明钱再记账）
        → 未命中：忽略（可能是无关 v4 池）
  6. Initialize：只为「本块刚创建、属于四类」的池补 poolId，写入对应明细 + 池登记
```

**池登记**（内存 + 明细表可重建）：`pool_id → token_address + category`。Pons 毕业后再补。v4 `Swap` **没有 token 地址**，没有这张表就无法把 Swap 归到四类。

Pons 未毕业：另有 `curve_address → token`。全链 `CurveBuy/Sell` 按曲线地址反查，不按工厂地址听买卖。

### 3.3 共享 vs 盘口私有

| 合约角色 | 归属 | 处理 |
| --- | --- | --- |
| 四类工厂 / LongLauncher / LaunchAndBuy | 私有 | 只进对应 Venue 创建 |
| o1 股票 Hook / o1 加密 Hook | 私有常量 | 创建时校验 hooks，填错打 `[错误]` 仍可按工厂分类入库（需求：分类跟工厂） |
| Pons 曲线 | 运行时发现 | 创建时写入 `launch_pons`，买卖用曲线事件 |
| PoolManager / 改版 Universal Router | 共享 | Swap 二次分发；Router **不是**用户 |
| Airlock / 其它 Doppler 产品 | ignore | 不发现为 Long |
| GMGN 等聚合器 | shared/aggregator | 多跳仍 Transfer 归因，`router` 记名字 |
| USDG / WETH / 股票 token | quote | 折 U 与配对名称 |

协议合约默认 **不是** 聪明钱。名单里显式出现才匹配（不建议把 Router 放进去）。

## 4. 四个适配器的职责

见图 12。每个适配器 **只准**做：认自己的 log、解领域对象、给出 Fill 的数量腿（quote/meme）。写库、名单、FIFO 在 app。

### 4.1 `venue/pons`

- 创建：Factory `TokenLaunched` 或经 LaunchAndBuy 的同笔创建。
- `creator_eoa` = `tx.from`；事件 deployer 另存。
- 买卖：`CurveBuy` / `CurveSell`；用户侧用事件 recipient（买）/ 对应卖侧，仍用 meme Transfer 交叉确认。
- 毕业：更新 `phase`、补 `pool_id`；之后成交走共享 v4 通道。
- Fill 数量：事件 `quoteIn/tokensOut` 或 `quoteOut/tokensIn`（含税实付）。毕业后改 Transfer 净额。

### 4.2 `venue/o1stock` 与 `venue/o1crypto`

- 创建：各自工厂 `Launched`。股票校验证后缀 `01`（不符仍入库并标记异常）；加密无此硬规则。
- `creator_eoa` = `tx.from`；事件 `creator` 常为 Deployer 合约，两列都要。
- 校验 hooks 是否为该路由的 LaunchHook。
- 买卖：不在适配器里扫全链 Swap，只消费共享通道里 **poolId 已登记且 category 匹配** 的 Fill。
- 用户地址：meme Transfer 最后一跳 EOA，不用 `Swap.sender` / `Trade.executor`。

两个包复制结构、不共用一个 `o1.Launch` 类型，避免 Hook/报价约束缠在一起。

### 4.3 `venue/long`

- 创建：仅 `LongLauncher.LaunchCreated`。
- 禁止用 Airlock `Create` 当发现源。
- `creator_eoa` = `tx.from`（样本等于 launcher）；代币 owner 是 Airlock，默认不当聪明钱。
- 买卖：同 o1，走共享 v4 + 已登记 poolId。
- quote = `numeraire`。不要假设 meme 永远是 token1。

### 4.4 共享 `venue/v4fill`（不是第五类盘口）

- 输入：PoolManager `Swap` + 同笔 Transfer。
- 查池登记得到 token 与 category。
- 输出：`Fill{Token, Quote, MemeAmount, QuoteAmount, User, Router}`。
- 不算「新盘」。未登记 pool 直接丢弃。

## 5. 与「再加第五类」的扩展方式

以后若加 Bags 等（当前需求明确不做）：

1. 调研文档增加入口与 topic。
2. 合约目录加 `venue=bags` 条目。
3. 新增 `venue/bags` + `launch_bags` + domain 类型。
4. 若仍走 v4，只把新 `pool_id` 登记进共享通道。
5. **不改** FIFO、评分、名单、HTTP。

禁止为赶工把新协议字段塞进 `launch_long` 或 `map[string]any`。

---

## 6. 解码失败

- 目录命中但 ABI 解不出：`[错误]`，该 log 跳过，水位仍前进。
- 创建成功但缺配对名称：配对记未知，不得用 Debot 名顶替。
- Fill 算不出 U：仍可记 quote 数量；`exec_usd` 空；不刷展示 U；不进评分。
- 禁止静默吞掉已知 topic 的解析错误。

## 7. 落地包结构（建议）

```text
internal/contracts/catalog.go     # 目录加载与校验
internal/venue/route.go           # address+topic → handler
internal/venue/pons/
internal/venue/o1stock/
internal/venue/o1crypto/
internal/venue/long/
internal/venue/v4fill/
internal/domain/launch_*.go       # 四类型，禁止共用一个 Launch
internal/domain/fill.go           # 成交腿，与盘口无关
internal/domain/fifo.go
```

一个文件不得同时：拉 RPC、解四种 ABI、写四张表、算 FIFO。那是 Fourmeme `handler` 在单 Manager 前提下才成立的写法，本链不成立。
