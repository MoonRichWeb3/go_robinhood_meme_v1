- 最新更新时间：2026-09-03 15:50 (UTC+8)
- 适用范围：Robinhood Chain 监听记账服务的进程、分层、存储与部署
- 来源：`docs/需求/01-产品需求说明书.md`；底稿 `docs/需求梳理/01-初识需求设定.md` §7–9；对照 `go_fourmeme_v3` 只借扫块骨架，不借 MySQL/下单

## 结论先行

v0 是 **一个进程、两件事**：扫链入库 + 本机只读查询。存储是 **一份 SQLite**，扫块独占写，HTTP 只读。四类盘口在领域层分类型，禁止一个万能 Launch。总图：图 1 上下文、图 2 容器、图 3 分层。

对照 Fourmeme：轮询收据的骨架可借鉴；领域必须拆盘口适配器。本仓库 **不包含** 自动交易模块。

## 1. 系统上下文

见图 1。边界：

- 入：链上收据/日志、SQLite 里的聪明钱名单、配置（RPC、起始块、刷价间隔）。
- 出：中文 stdout（Docker 同时写项目根 `logs/robinhood-meme.log`）、SQLite 行、只读 HTTP JSON。
- 不做：发交易、管私钥、公网鉴权后台。
- Debot/GMGN 网页不是事实源。

## 2. 进程与并发

见图 2、图 6、图 7、图 10。

**一个 Go 二进制**（go-zero rest 入口 + 扫块 goroutine）。理由：SQLite 单 writer；v0 流量与名单规模都小；名单热加载和刷价都要和扫块同库。

| 协程 | 职责 | 写库 |
| --- | --- | --- |
| 扫块 | 拉块 → 分流盘口 → 新盘/成交 | 写 `launch_*`（本期 pons/o1_crypto）、`wallet_events`、`sync_state`、`last_seen_at` |
| 刷价 | 默认 3s 把内存脏集合刷进 `launch_index.price_usd` | 经同一 writer 队列 |
| 名单 | ≤1s 或每块前重载 `status=active` | 只读 `smart_wallets` |
| HTTP | 健康检查、新盘列表、某钱包流水 | **只读** |
| 评分 | 定时或按事件阈值重算 | 只更新钱包分数列，走同一写入口 |
| 币安 ETH | 独立 HTTP 拉 `ETHUSDT` | **只写内存**，禁止第二 SQLite 写连接 |
| 过期清理 | 每小时分批删 7 天前 `wallet_events` | 同一 writer 队列；有界批次 |

约束：

- SQLite **一个写连接**（或串行写队列）。HTTP 用只读连接或 `PRAGMA query_only`。扫块、刷价、评分、过期删除都必须排队，禁止并行写。
- 扫块只在 RPC 读取阶段并发：每轮最多 `RH_MAX_BLOCKS_PER_TICK` 块，并发上限 `min(8, RH_MAX_BLOCKS_PER_TICK)`。RPC 返回可乱序，app 处理、重组判断和 SQLite 原子提交仍严格按块号串行；首个按序错误取消后续读取并停在失败块。
- 运营可在进程运行时改 `smart_wallets`（WAL + `busy_timeout=5000`）。刷新失败打 `[错误]`，沿用上一份有效集合，下一轮再试。
- 无界：脏代币集合、HTTP 查询必须有上限（条数/时间窗）。数字见 `docs/功能模块/10`（脏集合 5000）、`14`（列表 limit 50/200）。架构要求 **有界**。

链重组：只更新 `sync_state` 的块高与 hash，打日志，**不删已写入行**。

## 3. 分层

见图 3。按职责拆，禁止在入口文件里混配置、扫块、解析、写库。

```text
cmd/                         启动：读配置、组装依赖、起 HTTP 与扫块
internal/config/             结构体与校验（RPC、工厂地址、间隔）；不含业务规则
internal/app/                编排：一块如何走完、刷价节拍、名单刷新节拍
internal/domain/             纯业务：四类 Launch、钱包、成交、FIFO、评分
internal/venue/              盘口适配器（见 02）：链日志 → domain
internal/chain/              RPC、收据、水位、有界 callTracer；不知道 Pons/Long 业务字段
internal/contracts/          合约目录：地址、角色、归属盘口（见 02）
internal/store/              SQLite；按表分文件；主键/大小写规则落在这里
internal/wallets/            当前有效名单（内存快照，源是 SQLite）
internal/price/              成交折 U、脏集合、3s 刷目录；ETH 读币安内存缓存；缺价返回错误而非 0
internal/logx/               中文结构化日志
internal/httpsvc/            go-zero 只读 handler，只调查询，不解析 ABI
```

| 层 | 可以依赖 | 不可以 |
| --- | --- | --- |
| cmd / app | 下面各层 | 在 main 里写解析或 SQL |
| domain | 无基础设施 | 引用 `ethclient`、SQL、HTTP |
| venue | domain、contracts | 直接 `INSERT`；成交写库由 app+store 做 |
| store | domain 类型 | 解析 topic、算 FIFO |
| chain | 无业务枚举 | `if pons { ... }` 堆在收据循环里 |

测试：FIFO、评分、主键拼接、地址规范化必须能 **脱离 RPC** 单测。盘口解码用固定收据夹具，不打真实节点做主验证。

对照底稿目录名：`parser/pons|…` 与本文 `venue/` 是同一层，落地时用 `venue`（盘口），避免和 go-ethereum `parser` 混名。

## 4. 主数据流（一块）

见图 5、图 13。

```text
chain 拉到块（收据或 logs）
    → app 刷新有效名单（若本块尚未刷新）
    → 按 contracts 目录分流到某个 venue（或共享 v4 Swap 通道）
    → venue 产出领域事件：Created / Graduated / Fill
    → Created：store 写 launch_* + launch_index（price_usd 空）
    → Fill：
         原生 ETH + 已归因用户 + 收据严格单 Swap → 独立 trace RPC 算用户净额
         已入库代币 → 内存记下最新成交单价 U（脏）
         用户地址 ∈ 有效名单 → 当场写 wallet_events + 中文买卖/发盘日志
         卖出 → domain FIFO（可打已实现盈亏U）
    → 更新 sync_state
每 3s：脏代币 UPDATE launch_index.price_usd + [价格] 日志
```

幂等：

- 交易：主键 `id` 冲突则跳过。
- 新盘：`token_address` 已存在且分类相同则忽略；分类不同则 `[错误]` 且不覆盖。

`id` 算法（需求已拍板，架构在 store 落纯函数）：

```text
id = 左补零(block_number, 8) + 左补零(tx_index, 4) + 左补零(log_index, 4)
```

缺 `tx_index` / `log_index` 当 0。超过宽度不截断，打 `[错误]`。`log_index` 用协议事件在收据中的下标，不用 Transfer。

## 5. SQLite

见图 9、图 10。来源：底稿 §7，与需求 §2.3 / §6 对齐。

| 项 | 决定 |
| --- | --- |
| 文件 | 容器内 `/data/robinhood_meme.sqlite3`，主机 `./data` 挂卷 |
| 模式 | WAL；`busy_timeout=5000`；单 writer |
| 迁移 | `migrations/001_init.sql` 起线性文件，启动执行 |
| 备份 | 停写或 `VACUUM INTO` |
| 金额 | 链上最小单位用 INTEGER 或 TEXT，不用 REAL 存 wei；评分可用 REAL |
| 时间 | UTC |
| 禁止 | `raw_json` / 原始回执；无意义自增代理主键；明细表价格列 |

| 表 | 主键 | 主写 |
| --- | --- | --- |
| `smart_wallets` | `address` 小写 | 运营（sqlite3）；进程只更新分数、`last_seen_at` |
| `wallet_events` | 拼接 `id` | 扫块 |
| `launch_index` | `token_address` | 扫块建行；刷价协程更新 `price_usd` |
| `launch_pons` / `launch_o1_stock` / `launch_o1_crypto` / `launch_long` | `token_address` | 扫块；**四表四模型** |
| `quote_assets` | `address` | 配置/启动种子 + 必要时补充 |
| `sync_state` | `name`（如 `rh_4663`） | 扫块 |

地址 / `tx_hash` / `pool_id`：写入小写带 `0x`；列 `COLLATE NOCASE`。查询缺 `0x` 先补再比。

若用 GORM：四个 Launch **四个 Model**，主键关自增。禁止 `map[string]any` 当主模型。

ORM 选型（架构建议，实现时可改库不改边界）：GORM 能开 SQLite 即可；不要把 Fourmeme 的 MySQL 模块搬过来。

## 6. Docker 与配置

见图 4。来源：底稿 §7.4。需求只要求可容器化、密钥不进镜像。

```text
镜像：仅二进制 + 迁移 SQL
挂载：robinhood-data → /data；./logs → /logs
环境：
  RH_RPC_ENDPOINTS_FILE  默认 configs/rpcs.json；[{rpc,qps}] 扫块池
  RH_RPC_URL             无 JSON 时回退；生产用自有节点（公开 RPC 无 UA 会 403，打太快 429）
  RH_TRACE_RPC_URL    可选；空则禁用；非空时独立建客户端并核对 chainId
  RH_TRACE_TIMEOUT_MS 默认 8000
  RH_FROM_BLOCK       起始块
  LOG_LEVEL
  RH_LOG_DIR          可选；Compose 为 /logs
  HTTP 绑定           默认本机
  PRICE_FLUSH_SEC     默认 3
  WALLET_RELOAD_MS    默认 ≤1000
不把 RPC 密钥写入镜像或 git。
```

健康检查：进程存活 + `sync_state` 落后块数 + `/health`。

公开 RPC 与 User-Agent 细节见调研 `01`/`04`，属于适配器实现，不在此复制。

## 7. 只读 HTTP

见图 8。go-zero rest，与扫块同进程。

v0 接口路径见 `docs/功能模块/14-只读HTTP.md`：

- 健康：能否连上库、扫块是否在推进
- 新盘列表：读 `launch_index`
- 某钱包流水：读 `wallet_events`

无写接口、无鉴权、默认绑本地。优质项目用 SQL 现算，不建 `project_signals`。

## 8. 明确不进本架构

- `internal/trade`、下单、私钥
- Bags / hood.fun / pools.trade / Bankr 适配器
- 多链、第二套数据库
- 为每个盘口复制一套 FIFO/评分

ETH 喂价：独立 HTTP 拉币安（调研 `10`），只进内存。股票喂价仍未就绪返回错误，**禁止默认 0**。本期不落地 o1 股票与 Long。

## 9. 质量属性

见图 14。对应需求非功能与验收。

| 属性 | 指标 / 场景 | 架构手段 |
| --- | --- | --- |
| 时效 | 跟上链上创建与已入库成交；名单 ≤1s；展示 U 默认 ≤3s | 有界并发预取、按序提交；名单快照；脏集合刷盘 |
| 正确 | 同一事件不双写；分类冲突不覆盖 | 自然键主键；单 writer |
| 持久 | 重启不丢；卷上 SQLite | 挂卷；启动跑迁移 |
| 可观测 | 中文结构化日志；健康检查 | logx；`/health` + 水位 |
| 安全 | 无热私钥；密钥不进镜像；HTTP 默认本机 | 无 trade 模块；env 注入 |
| 可测 | FIFO/评分/主键脱离链 | domain 纯函数；venue 用收据夹具 |
| 可扩展 | 第五类不改 FIFO | 合约目录 + 新 venue 包 |
| 降级 | 币安失败超 stale 窗 / 无股价喂价 | U 空、打缺价、禁止写 0 |

轮询间隔相对 ~100ms 出块：架构要求 **可配置且小于块时间的整数倍等待不可接受**（例如 3s 一轮询会落后很多块）。默认毫秒见 `docs/功能模块/01-扫块与水位.md`（`RH_POLL_MS=80`），落后块数进健康检查。追赶时只并发网络读取，不放宽单块事务边界；429/5xx 由轮询外层统一退避，预取层不做内部重试。

## 10. 横切

| 主题 | 决定 |
| --- | --- |
| 时间 | 一律 UTC；日志同时可带处理时间与链上时间 |
| 日志 | 仅 logx 打给人看的行；禁止业务里 `fmt.Println` 英文键 |
| 配置 | `internal/config` 校验；工厂地址来自合约目录；名单不进配置文件 |
| 错误 | 已知 topic 解失败必须 `[错误]`；水位仍前进（图 13） |
| 幂等 | `wallet_events.id`；`token_address`+分类 |
| 地址 | 写入小写 `0x`；查询 NOCASE；缺前缀先补 |
| 有界 | 脏集合、HTTP 列表必须有上限，避免全表无界扫 |
| 重组 | 更新 `sync_state` hash，不因分叉删行。交易表过期删除见 ADR-10，与重组无关 |

## 11. 架构决策（ADR）

| ID | 决策 | 理由 | 后果 |
| --- | --- | --- | --- |
| ADR-1 | 单进程 + SQLite | v0 单写、名单与刷价同库 | 不能水平扩写；备份靠卷 |
| ADR-2 | go-zero 只读 HTTP 同进程 | 需求已选框架；少一套部署 | HTTP 故障不应阻塞扫块（实现时独立 goroutine + 超时） |
| ADR-3 | 四 venue 四表，禁止万能 Launch | 协议字段互斥 | 多一套样板，换来类型安全 |
| ADR-4 | 合约目录分流 | 地址多、禁止魔法数 | 启动缺目录则拒绝起来 |
| ADR-5 | v4 Swap 共享二次分发 | Swap 无 token 地址 | 必须维护 pool 登记 |
| ADR-6 | 展示价 3s 批量 | 避免每笔 UPDATE | 列表最多延迟约 3s |
| ADR-7 | 重组不回滚 | 需求拍板 | 可能有分叉幽灵行 |
| ADR-8 | 无自动交易模块 | v0 只记账 | 目录里不出现 trader |
| ADR-9 | ETH 走币安公开行情 HTTP | 用户指定独立接口；无 Key | 股票仍缺价；USDT≈USD |
| ADR-10 | `wallet_events` 只留 7 天、小时分批删 | 控制库体积、避免一次 DELETE 锁死扫块 | FIFO/评分只看见窗内数据 |
| ADR-11 | 原生 ETH 用独立 callTracer RPC 且仅限单 Swap | Swap delta/tx.value 不能代表聚合器扣费后用户净额 | 第三方不可用时 quote/U 为 NULL，水位继续 |

## 12. 风险与待确认

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 公开 RPC 403/429 | 扫块中断 | 生产自有节点；开发限速 + UA（调研） |
| `eth_getBlockReceipts` 在自有节点行为 | 扫块实现 | 适配器可回退 getLogs；选型在落地验证 |
| SQLite 与 sqlite3 同时写名单 | `busy` | WAL + timeout；扫块串行写 |
| 池登记丢失 | Swap 无法归类 | 从 `launch_*` 重建；进程启动加载 |
| 喂价长期缺失 | 无 U、无评分 | 需求允许空；健康检查可暴露「缺价笔数」 |
| 100ms 块 + 解析慢 | 落后 | 健康检查落后块；禁止在扫块里做无界 HTTP |
| 第三方 trace 限流或方法下线 | 原生 ETH 成交无 quote/U | 单笔超时、响应/深度/节点上限；失败留 NULL 且继续提交 |

落地前必须验证（不在本文假装已验证）：自有 RPC 的收据接口、公开 RPC 仅开发。
