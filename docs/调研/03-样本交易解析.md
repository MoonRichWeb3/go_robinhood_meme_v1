# 03 样本交易解析

- 最新更新时间：2026-09-01 15:50 (UTC+8)
- 适用范围：用用户给的两笔 tx 标定「真实成交长什么样」
- 来源：官方 Blockscout `GET /api/v2/transactions/{hash}` 与 `/logs`；rh-scan 仅作页面交叉

两笔都成功，都是 **已有池子上的 swap**，都不是新币创建、也不是 Fourmeme 式 TokenManager 内盘。

## 样本 1：Uniswap Universal Router → v4 单跳买 LKDOG

- 浏览器：<https://rh-scan.com/tx/0x69a366257a60e04646e009c316ba8140a41fda7961c09a63fb987f784d57ea2d>
- 官方：<https://robinhoodchain.blockscout.com/tx/0x69a366257a60e04646e009c316ba8140a41fda7961c09a63fb987f784d57ea2d>
- Hash：`0x69a366257a60e04646e009c316ba8140a41fda7961c09a63fb987f784d57ea2d`
- 区块：`51540363`，时间 `2026-09-01T07:26:51Z`

| 字段 | 值 |
| --- | --- |
| from | `0x1342f0040FA2D92FC20aEf89aBf77FA781d8bFe7`（EOA + EIP-7702 委托） |
| to | `0x8876789976dEcBfCbBbe364623C63652db8C0904` Universal Router |
| value | `0.3 ETH` |
| method | `execute` / `0x3593564c` |
| commands | `0x10`（仅 V4_SWAP） |
| deadline | `1788249406` |

### 解码结论

- 这是 **ETH → meme** 的 v4 exact-in。
- PoolManager `Swap`：
  - poolId `0x0f7d9685fe6a8a7b098f454137b872676f3c2bc39f3da08f1f0afbc306547fef`
  - sender = Universal Router
  - amount0 = `-300000000000000000`（池收入 0.3 native ETH）
  - amount1 = `+14525430936839530829052623`（池付出 LKDOG）
- Token：`0x95f3f3D621F8e540B0E634f841555D2c8d14D921` Lucky Dog / LKDOG，18 位，总量 1e9。
- Blockscout 合约名 `UERC20`（Uniswap 发射台代币模板）。
- Transfer：PoolManager → 买家，数量与 Swap amount1 一致。
- calldata 里可见 `fee=2500`（`0x9c4`）、`tickSpacing=25`（`0x19`）、hooks 为 0。

**建议 / 推断：** 池参数与 pools.trade 当前路径（ETH 计价、fee 2500、tick 25、无 hook）一致，LKDOG 很大概率是 pools.trade / Uniswap LiquidityLauncher 盘，而不是 Pons/Bags（后两者毕业池带自己的 hook）。

### 对监听的意义

过滤 `address=PoolManager` 且 `topic0=Swap` 就能抓住这笔。再配 `Transfer` 确认买家拿到的 token。`sender` 是 Router 不是用户，用户要从 tx.from 或 token Transfer 的 `to` 取。

### 对交易的意义

自建买入应复制这条路径：

1. 组 `PoolKey`（本例 currency0=ETH 零地址，currency1=LKDOG，fee=2500，tickSpacing=25，hooks=0）。
2. `zeroForOne=true`（ETH → token）。
3. `execute(0x10, [SWAP_EXACT_IN_SINGLE+SETTLE+TAKE], deadline)`，`minHopPriceX36=0`，`value=amountIn`。
4. 用 V4Quoter 模拟出 `amountOut` 再扣滑点。

## 样本 2：GMGN Swap Router 多跳买 WHO

- 浏览器：<https://rh-scan.com/tx/0x223103b5be0df624cab54a41caaa36b0a6839cf311828ff8f0ad2b705b24acfa>（本次 Cloudflare 拦截）
- 官方：<https://robinhoodchain.blockscout.com/tx/0x223103b5be0df624cab54a41caaa36b0a6839cf311828ff8f0ad2b705b24acfa>
- Hash：`0x223103b5be0df624cab54a41caaa36b0a6839cf311828ff8f0ad2b705b24acfa`
- 区块：`51532438`，时间 `2026-09-01T07:13:32Z`

| 字段 | 值 |
| --- | --- |
| from | `0x51727690B8EDA32EE9B44973d543a7F9c04c3F47`（普通 EOA） |
| to | `0x65050A9b7E5075A2bA5cED7b1b64EE66262c40Dc` |
| value | `0.2 ETH` |
| method | `0x4d819a2a`（未在浏览器解码；4byte 为 `swap(tuple[],address,uint256,uint256,uint256)`） |
| gas used | 477679（明显高于样本 1 的 106454，符合多跳） |

### 资金路径（按 token_transfers 顺序）

1. 包装：mint WETH `0.198` 到 Router（0.2 里扣了手续费/包装差）。
2. Uniswap **v3** 池 `0x52e65B17fB6E5BA00Ed806f37Afcd2DaA50271Ca`：WETH → USDG。
3. Uniswap **v4** PoolManager：USDG → `pHOOD3x`（`0xe24CABDf76DD1c2576049167eB1755C84b985C36`，Arcus 3x 多头，不是普通 meme）。
4. Uniswap **v4** PoolManager：pHOOD3x → WHO `0xA696ca9CFB37a6Bb01a92B53eb8f221ba59B3Afd` Whoooo，1e9 供应。
5. 最终 Transfer：PoolManager → 用户 `165020822905299581451897089` WHO。

calldata 里还能看到 hop 结构：WETH、USDG、v3 池、两个 v4 hook（`0xFa3DA20ec661AA26F9F93e4421fAb6989c4B4800`、`0x1c909636cfb551e257603062806da4929d44a8cc`）、PoolManager。

**建议 / 推断：** 这是聚合器为了成交 WHO，绕了 USDG 和杠杆代币，不是「发射台内盘一跳」。自建 bot 若只跟 meme，应识别最终 token 为 WHO，不要把中间的 pHOOD3x 当成标的。

### 对监听的意义

- 只听 Universal Router 会漏掉 GMGN 路由的成交。
- 只听 PoolManager Swap 能看到最后一跳（pHOOD3x/WHO），但中间还有 v3 Swap。
- 跟「聪明钱买 meme」：以 **用户地址最终收到的非 WETH/非 USDG ERC-20** 为准，再用 poolId/hooks 判断发射台。

### 对交易的意义

不要为了买 WHO 去复刻这条 4 跳路径。先查 WHO 的直接 v4 PoolKey（ETH 或 WETH 对），能单跳就单跳。只有深度不够时才考虑聚合器。
